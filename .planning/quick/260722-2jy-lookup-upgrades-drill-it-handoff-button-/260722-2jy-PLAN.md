  <action>
    DECISION (document verbatim in the SUMMARY): a non-chord-tone bass such as C/D is REJECTED via the existing unrecognized path, not accepted. Rationale: tonal parses C/D as non-empty but returns root:'' and a negative bass interval ("-7m") that collapses to roleForDegree's DoS-safe 'root' fallback, colliding with the actual root and corrupting the re-sort. tonal reliably fills chord.root with the bass note ONLY when the bass is a genuine chord tone (a true inversion: root === bass); a non-chord-tone slash yields root === ''. So the guard chord.bass !== '' && chord.root === '' cleanly rejects non-inversions. This matches the feature framing ("inversion support") and is more robust than displaying a mis-modeled note set. (Verified against tonal 6.4.3: C/E root:"E", Cmaj7/G root:"G", G7/F root:"F", Am7/G root:"G"; C/D root:"".)

    In src/lib/theory/types.ts: add an optional field bass?: string to the ChordResult interface, documented as "The bass (lowest) note with accidental glyph for a slash-chord inversion, e.g. 'E' for C/E. Undefined for a plain root-position chord." Place it near the notes field.

    In src/lib/theory/chord.ts, inside spellChord after Chord.get(normalized) and the existing chord.empty guard: add a reject branch — when chord.bass is a non-empty string AND chord.tonic is set but chord.root is an empty string, return the same unrecognized shape the chord.empty branch returns (this routes C/D through didYouMean/hint on the page). Only re-sort and only attach bass when chord.bass is non-empty; leave plain chords byte-identical (bass stays undefined).
