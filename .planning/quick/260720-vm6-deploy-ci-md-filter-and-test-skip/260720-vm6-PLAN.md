<objective>
Two independent CI-cost optimizations to `.github/workflows/deploy.yml`, both safe-by-default:

1. Doc-only push filter: add `paths-ignore` to the `push` trigger so pushes whose changed files are entirely documentation (`**.md`, `.planning/**`, `docs/**`) do not spin up a deploy. `workflow_dispatch` is untouched, so manual deploys always work. (DEPLOY-CI-01)
2. Redundant-test skip: `ci.yml` already runs the identical suite on every `pull_request` (against the PR merge ref). When a push to main is a merge commit whose merged tree is byte-identical to its PR-head parent's tree — i.e. the same content was already tested green on the PR — the `gate` job skips re-running npm ci / test / check and succeeds, so build-push proceeds immediately. Squash merges and direct pushes have no second parent, so tests always run. (DEPLOY-CI-02)

Purpose: stop wasting runner minutes on deploys that change nothing deployable, and on re-testing content a PR already tested.
Output: an updated `.github/workflows/deploy.yml`.
</objective>

<task type="auto">
  <name>Task 2: Skip redundant gate tests when the merge tree was already tested</name>
  <files>.github/workflows/deploy.yml</files>
  <action>
Modify the `gate` job only (do not touch `build-push` or `deploy`). Four changes:

1. Grant the gate job read scope for the check-runs query. Add a job-level `permissions:` mapping to `gate` with `contents: read` and `checks: read`. (Top-level permissions is `contents: read`; the job-level block overrides it for gate, so include both keys.)

2. Give the existing `actions/checkout@v4` step in gate a `with:` block setting `fetch-depth: 2`. Depth 2 is required so a merge commit's second parent (`HEAD^2`) and its tree object are present in the shallow clone; the checkout must stay the FIRST step in the job.

3. Insert a new step immediately after checkout named "Decide whether gate tests can be skipped" with `id: decide`. Give it `env:` `GH_TOKEN: ${{ github.token }}` and `REPO: ${{ github.repository }}`. Its `run:` script (bash) does exactly this: initialise `skip=false`; if `git rev-parse -q --verify 'HEAD^2'` succeeds (this push is a merge commit), capture the merge tree from `git rev-parse 'HEAD^{tree}'` and the PR-head tree from `git rev-parse 'HEAD^2^{tree}'`; when those two trees are equal, resolve the PR head sha via `git rev-parse HEAD^2` and query `gh api repos/$REPO/commits/<pr_head_sha>/check-runs` with `--jq '[.check_runs[] | select(.name == "test") | .conclusion] | first'`; if that value is `success`, set `skip=true`. Always finish by writing `skip=$skip` to `$GITHUB_OUTPUT` and echoing the decision for the log. Keep every branch conservative: any failure to verify HEAD^2, any tree mismatch, or a check-run conclusion that is not `success` leaves `skip=false` so tests run. Squash merges and direct pushes have no `HEAD^2`, so they naturally fall through to `skip=false`.

4. Guard the work steps. Add `if: steps.decide.outputs.skip != 'true'` to the `actions/setup-node@v4` step and to all five run steps (`npm ci`, `npm run test`, `npm run check`, the server `npm ci`, and the server `npm run test`). Do NOT guard the checkout step or the decide step. When skip is true these steps are skipped; skipped steps are not failures, so the gate job still concludes success and build-push (needs: gate) proceeds.

The `test` check-run name in the jq filter matches `ci.yml`'s job id `test`; if the executor confirms the ci job is later renamed, update the filter to match. Do not weaken the AND: skip requires merge-commit AND tree-equality AND ci test == success.
  </action>

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| git push -> deploy workflow | Pushed commit content (including merge parents/trees) drives the skip decision that gates whether tests run before build-push/deploy. |
| runner -> GitHub API (`gh api ... /check-runs`) | Read-only query for the ci `test` conclusion on the PR head sha. |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-vm6-01 | Tampering | gate skip decision | high | mitigate | Skip requires ALL of: HEAD^2 exists (merge commit) AND `HEAD^{tree}` == `HEAD^2^{tree}` (merged content byte-identical to already-tested PR head) AND the ci `test` check-run on the PR head concluded `success`. Any failure or mismatch leaves skip=false, so untested content is always tested. |
| T-vm6-02 | Elevation of Privilege | gate job permissions | low | mitigate | Job gets only `checks: read` added (plus existing `contents: read`); no write scopes. GH_TOKEN is the default `github.token`, read-only for this job. |
| T-vm6-03 | Spoofing | ci `test` check-run lookup | medium | mitigate | Confirmation reads the conclusion of the check-run named `test` on the specific PR-head sha (HEAD^2), not a branch-level or attacker-supplied ref; the sha comes from the merge commit's own parent pointer. |
| T-vm6-04 | Denial of Service (missed deploy) | paths-ignore filter | low | accept | A push mixing docs + code still deploys (paths-ignore only skips all-doc pushes); doc-only pushes intentionally do not deploy, and `workflow_dispatch` remains available for a forced manual deploy. |

No package-manager installs are introduced by this change, so no package legitimacy gate applies.
</threat_model>
