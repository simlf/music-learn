# v2.1 Improvement Backlog (research-derived)

**Generated:** 2026-07-15 (autonomous overnight run, after v2.0 completion)
**Sources:** two parallel research passes — learning-science (cognitive/music-pedagogy literature) and competitive-feature (iReal Pro, jazzchords.app, Hooktheory, Soundslice, EarMaster) — cross-referenced against the shipped v2.0 codebase and gaps observed during v2.0 verification.

Ranked by (impact on the core value: chord-symbol fluency) × feasibility. The two research passes converged on the same top items.

## Tier 1 — build first (high value × high feasibility)

### I-01. Mastery-criterion fix: successive relearning (S) — CONFIRMED DEFECT
`deck.ts deriveCellState` labels a card `mastered` the instant `card.state === State.Review` (after ONE successful FSRS grade). This over-claims mastery and misleads the recall map + any confidence signal. Observed live during v2.0 verification (one Good grade on C flipped it to "Mastered").
Evidence: Rawson & Dunlosky successive-relearning — durable mastery requires correct retrieval across MULTIPLE separate sessions/days, not one success.
Build: add a cross-day correct-review counter to `CardRecord` (schema migration via the existing Zod boundary), only render `mastered` after State.Review AND correct re-grade on >= 2 distinct calendar days; intermediate state stays `weak`/`due`. Update `deriveCellState` + RecallMap tests.

### I-02. Progression drills / functional harmony in context (L) — HIGHEST FEATURE VALUE
Both passes ranked this #1 for the core value. Real sheet music is progressions (ii-V-I, turnarounds), not isolated symbols; situated practice builds the reading-in-context skill that isolated drilling does not.
Build: extend `src/lib/practice/songs.ts` (already stores ordered chordSymbols) with a `key` field + roman-numeral derivation (tonal `RomanNumeral`/`Progression`); add a progression drill that presents the canonical jazz progressions (ii-V-I major+minor, I-vi-ii-V, tritone sub) chord-by-chord and reveals the functional relationship. Reuse the see-play/formula-build/hear-name mode machinery with a `contextKind: 'isolated' | 'progression'` tag so progressions unlock once single chords are stable. Keep to ~6 canonical progressions (avoid full-harmony scope creep).

### I-03. Tempo / speed fluency drill (S-M)
Trains the "instantly" in the core value (fast symbol->hand mapping, automaticity) which no current mode trains (all self-paced). Check `answerTelemetry.ts` — latency may already be logged.
Build: tempo slider + Tone.js click (already a dep) gating drill pace, auto-increment on streaks (iReal Pro pattern); surface per-chord slow spots for extra reps (jazzchords.app pattern). Do not let speed penalize FSRS scheduling.

## Tier 2 — high value, larger or thinner-evidence

### I-04. Rootless / shell voicing mode (L)
The LH shape competent players actually use ("know what to play" = a compact shell 3rd+7th or rootless A/B voicing, not a root-position stack). jazzchords.app validates demand.
Build: add a voicing-style parameter (root / shell / rootless-A / rootless-B) to `construction.ts` + `matchChord`; accept partial/inverted note sets. Must work with on-screen click input (MIDI-optional).

### I-05. Confidence / JOL capture + calibration view (S-M)
Elicit "How sure? Low/Med/High" before reveal in RecallSession; log alongside FSRS grade; surface a confidence-vs-correctness chart. Turns "confident-but-wrong" cards into a targetable category (the population most likely to fail cold in real playing).

### I-06. Scaffold fading / expertise reversal (S)
Hints that help novices hurt transfer once mature. Tie hint availability to `card.state`/stability: full hints for New/Learning, suppressed/after-wrong-only for mature Review cards. Protects against the "still needs the crutch after mastered" failure (compounds with I-01).

### I-07. Hear-it-back on every correct answer (S)
Auto-play the voiced chord via Tone.Synth after any correct answer (toggle-able) so ear + hand reinforce together. Cheap multi-modal win.

## Tier 3 — later / deprioritized

- **I-08. Lead-sheet snippet read-through (M):** chord-symbols-in-time play-through of a song's progression at adjustable tempo (skip real staff engraving — high cost, low marginal fluency gain).
- **I-09. Ear-training progression redesign (M):** stage hear-name as quality-only (maj/min/dom/half-dim) before full symbol naming. Solid evidence but ear training is secondary to the reading/motor core value.
- **I-10. Blocked-then-feedback test mode for mature cards (M):** withhold feedback to end-of-block for Review cards. Evidence is the least settled; build cautiously.
- **I-11. Error-driven confusable-pair drilling (S-M):** drill commonly confused pairs (m7 vs m7b5, maj7 vs 6). Cheap if the wrong-selection is already logged; needs a schema add otherwise.
- **I-12. Cross-device sync (M):** lightweight serverless KV/D1/Turso push-pull of the Dexie store, single-user token. Explicitly a "later" concern in project docs; build only if per-device divergence becomes painful.
- **I-13. Web MIDI play-to-answer (L):** keep DEFERRED (needs hardware; Safari/iOS never support it). Build everything above MIDI-optional first, wire MIDI as a thin input adapter later.

### Explicitly skipped (scope creep vs core value)
Full staff-notation engraving; backing-track/full-band audio; social/leaderboard gamification; from-scratch general ear training (orthogonal to the reading/motor core value); full delayed-feedback rearchitecture (evidence too mixed).

## Suggested milestone (v2.1 "Fluency & Retention")
Order: I-01 (mastery fix, bug) -> I-02 (progressions, core value) -> I-03 (tempo/speed) -> I-04 (voicings) -> I-05/06/07 (retention polish bundle). Tier 3 as a standing backlog.
