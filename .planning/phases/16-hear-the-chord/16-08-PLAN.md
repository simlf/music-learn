<interface_context>
Depends on plan 16-07 (wave 1), which makes `playArpeggio` accept
`{ staggerMs: number; startDelayMs?: number }` and voice ascending via `toAscendingPitches`.
This plan wires `startDelayMs` and reuses `toAscendingPitches` to derive per-note octaves.

Key facts confirmed in source:
- `construction.earnedNotes` is a `SpelledNote[]`; `letters = earnedNotes.map((n) => n.letter)`
  are DISPLAY glyphs (e.g. "E♭", "F♯"), verbatim in root→3rd→5th→7th (chord) / ascending
  scale-degree (scale) order.
- `toAscendingPitches(letters)` (from `$lib/audio/voicing`) returns ASCII pitches WITH octaves
  (e.g. "F#5"), one per input, in the same order. For a scale it walks octaves upward.
- `PianoKeyboard`'s physical-key octave for a rendered key comes from
  `octaveForWhiteIndex(key.index)` / `octaveForBlackAfterWhiteIndex(key.position - 1)`, whose
  `BASE_OCTAVE = 4` is documented to "match the audio voicing's octave 4" — so
  `toAscendingPitches` octaves line up with the keyboard's octaves for the phase's chords and
  diatonic scales.
- `flashWrongKey?: { letter: string; octave: number }` + `flashWrongClass(letter, octave)` is
  the existing octave-discriminating pattern to mirror (PianoKeyboard.svelte:136, 509-513).
- Current pending wiring: BuildSession `pendingLetters` state (line 96), seeded/cleared in
  `startArpeggioRoll` (407/412-414/422), reset in `resetSessionUiState` (165), passed to
  `PianoKeyboard` at line 873 as `pendingLetters={pendingLetters}`; consumed by
  `pendingClass(letter, role)` (PianoKeyboard.svelte:533-534) and its two template call sites
  (white ~line 559, black ~line 607).
</interface_context>
