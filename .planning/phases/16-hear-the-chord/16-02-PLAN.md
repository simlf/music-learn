<objective>
Give `PianoKeyboard.svelte` two additive, opt-in capabilities the BUILD reveal needs: a re-triggerable one-shot `pulse-once` on the role-lit keys (driven by a bumped `pulseToken`), and a `pendingLetters` set that dims not-yet-sounded keys during the study-mode arpeggio roll via a `--pending` state.

Purpose: HEAR-01 needs the lit keys to pulse in time with the chord strike; HEAR-02's study roll needs each key to sit dimmed ("pending") until its note sounds. Both are presentational and gated so every existing render (display, interactive, inspect, construct) stays byte-identical when the props are omitted.
Output: New `pulseToken` and `pendingLetters` props, `pulseClass`/`pendingClass` helpers, the `--pending` CSS rule, and a dedicated component test.
</objective>

## Artifacts this phase produces (this plan's slice)

- `pulseToken?: number` prop on `PianoKeyboard.svelte` — bump to re-fire `.pulse-once` on role-lit keys.
- `pendingLetters?: Set<string>` prop on `PianoKeyboard.svelte` — drives `.piano-keyboard__key--pending` on already-role-lit keys.
- `pulseClass(letter, role)` and `pendingClass(letter, role)` class-composition helpers.
- `.piano-keyboard__key--pending { opacity: 0.28; }` CSS rule (component-scoped), with reduced-motion handled by the shared app.css block from Plan 16-01.
