<objective>
1B — Drills question-first reflow (phone portrait). Collapse the LevelPicker card, mode tabs, and SongFilterToggle into one compact strip that opens a bottom sheet, put the prompt directly under the strip, and keep the keyboard + Check in the thumb zone so there is no per-question scroll on a phone. Desktop is left exactly as it is today.

Purpose: The drills page currently stacks ~620px of chrome above the question on a phone, forcing a scroll on every question — the single biggest daily-friction point. This is the biggest daily-friction win in the phase and ships first.

Output: A shared `BottomSheet.svelte` primitive (reused by 1A), a phone-only compact strip in `drills/+page.svelte`, a phone-only grid reflow, and three new i18n keys.
</objective>

Locked decisions from CONTEXT that bind this plan:
- Phone breakpoint = `max-width: 640px` (Tailwind `sm:` boundary). Phone-only custom CSS uses `@media (max-width: 639.98px)` to avoid a 1px overlap with `sm:` at exactly 640px (UI-SPEC "Breakpoint precision").
- Collapsed strip is PHONE-ONLY. Desktop keeps the current full LevelPicker card and existing layout.
- Keyboard is NOT a fixed/sticky dock — it stays in normal document flow via the existing grid. The user previously rejected a fixed-bottom keyboard dock (see STATE.md [[keyboard-inline-not-docked]]).
- Reorder via the existing grid-area layout, not DOM reorder.
- No em dashes in any UI copy; all copy bilingual.
- Active-state affordance (strip open state) reuses LocaleToggle's active-segment treatment (ink fill / paper text), never vermilion.

Preview-harness limitation: this app cannot hydrate in the preview pane (null-origin SSR). Verify headlessly with Vitest + curl-SSR + CSS assertions; sheet slide transitions and exact perceived spacing are flagged for on-device eyeballing.
</context>
