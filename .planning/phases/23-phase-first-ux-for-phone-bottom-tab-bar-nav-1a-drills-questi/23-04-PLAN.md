<objective>
1A — Bottom tab bar navigation (phone only). Move nav to a thumb-reachable fixed bottom bar on phones (Lookup, Drills, Recall, Songs, More-sheet), slim the phone header to brand + StreakBadge, and add bottom padding so content clears the bar. Desktop keeps its full masthead unchanged. This is the layout-wide change, so it ships last (Wave 3), wrapping the finished pages.

Purpose: The masthead wraps brand + streak + EN|FR + 8 nav links into ~120px of top chrome — the worst one-handed reach zone with ~30px link targets. A bottom tab bar puts primary nav in the thumb zone.

Output: A responsive masthead + phone-only bottom tab bar + More sheet (reusing BottomSheet) in `+layout.svelte`, viewport-fit=cover in app.html, a shared tab-bar clearance rule in app.css, one new i18n key, and updated layout-rendering tests.
</objective>

Locked decisions from CONTEXT / UI-SPEC:
- Fixed bottom bar shown only at phone width. Use `@media (max-width: 639.98px)` in custom CSS (not literal 640px) to avoid a 1px overlap with Tailwind `sm:`.
- 5 items: Lookup, Drills, Recall, Songs (real links) + More (button opening BottomSheet). 64px content-row height + `env(safe-area-inset-bottom)` padding beneath. Mono uppercase labels. Text labels only (no icon set exists in this project — do not introduce one).
- Active tab = LocaleToggle active-segment treatment: `background: var(--color-ink); color: var(--color-paper);`. NEVER vermilion (vermilion is reserved for practice reward/warning). More never carries the active fill.
- Chrome: `background: var(--color-paper-bright); border-top: 2px solid var(--color-ink);` (matches the app's 2px heavy-border language). Optional 2px ink vertical dividers between items (recommended, not load-bearing).
- More sheet contents in order: Build, Scales, Theory, Progress (existing nav.* keys, plain rows, min-height 44px, left-aligned, mono uppercase) -> a `border-top: 2px solid var(--color-ink)` divider -> the LocaleToggle, centered. This is the ONLY place LocaleToggle renders on phone (removed from the slimmed header).
- Slimmed phone header: brand (existing heading span) + StreakBadge variant="compact" only. No nav links, no LocaleToggle. Desktop header completely untouched (all 8 links + LocaleToggle, flex-wrap row).
- Bottom padding audit: every page whose main uses min-h-screen needs phone-only bottom clearance. Define ONE CSS custom property (e.g. `--tab-bar-clearance: calc(64px + env(safe-area-inset-bottom))`) in app.css and apply it via a phone-only media query to `main`, rather than hand-copying the calc into N page files. (Affected routes today: /, /build, /drills, /progress, /recall, /scales, /songs, /theory, /showcase.)
- Testids: keep `data-testid="masthead"` on ONE header element (see Task 1). Add `data-testid="bottom-tab-bar"` and reuse BottomSheet's `data-testid="bottom-sheet"` (optionally wrap with `data-testid="more-sheet"`).
- No em dashes; all copy bilingual.

app.html currently has `<meta name="viewport" content="width=device-width, initial-scale=1" />` with NO viewport-fit — so `env(safe-area-inset-bottom)` is 0 on notched iOS until `viewport-fit=cover` is added.

CRITICAL test interaction: jsdom does NOT evaluate media queries, so BOTH the desktop masthead nav and the phone bottom tab bar render into the DOM simultaneously. That duplicates the Lookup/Drills/Recall/Songs links and the LocaleToggle, which breaks any UNSCOPED `getByRole('link'/'button', ...)` on the layout. Both `tests/masthead.e2e.test.ts` and `src/lib/i18n/coverage.test.ts` render the layout and must be updated to scope those queries.

Preview harness cannot hydrate — active-fill contrast, sheet transition, and real-device notch/safe-area clearance are flagged for on-device eyeballing.
