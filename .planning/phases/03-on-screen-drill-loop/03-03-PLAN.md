## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| user click/keydown -> /drills page | Untrusted key selections drive matching and feedback |
| page -> matchChord / spellChord | App-controlled chord symbol + user-derived chroma set cross into pure logic |
| generated symbol -> ChordGlyph/instruction render | Symbol comes from the fixed proven matrix, rendered as text |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-03-07 | Tampering | selected-key -> played chroma mapping | medium | mitigate | Selected letters come only from the static keyboard layout; each is mapped via tonal Note.chroma to a bounded 0-11 value before matchChord. No free-form input reaches the matcher, so no injection or malformed-set path. |
| T-03-08 | Injection (XSS) | rendering question.symbol / note letters in the DOM | low | mitigate | Symbol and note letters originate from the fixed ROOTS x QUALITY_SUFFIXES matrix and tonal output, rendered via Svelte text interpolation (auto-escaped), never `{@html}`. No user-supplied string is interpolated. |
| T-03-09 | Denial of Service | question generation on load / Next | low | mitigate | generateQuestion is bounded and total (Plan 01); the construction-only loop here draws at most a few times to land a construction question, capped. |
| T-03-10 | Information Disclosure | in-session state | low | accept | No persistence, no network; answered/selected/feedback are ephemeral in-memory and reset on reload (D-10). |
| T-03-SC | Tampering | npm/pip/cargo installs | n/a | accept | No package installs in this plan; all dependencies already vetted in Phase 1. No legitimacy checkpoint required. |
