<objective>
Ship the user-visible half of the phase: a self-hiding masthead MIDI chip that both displays the live connection state and carries the connect gesture, its English and French copy, and its mount point in the root layout.

Purpose: MIDI-01 needs the connection state visible; MIDI-04 needs the app to show no MIDI chrome at all where Web MIDI is absent. Output: `MidiStatus.svelte`, its component test, eight `midi.status.*` message keys, and a four-line change to `+layout.svelte`.

They are grounded in the masthead conventions already in `+layout.svelte`, `StreakBadge.svelte`'s self-hide rationale, and `MicCheckPanel.svelte`'s mono status-register label treatment.

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| USB MIDI hardware to DOM | The device-reported `name` string crosses from the instrument's USB descriptor into rendered masthead markup. A hub, a generic adapter, or a spoofed virtual MIDI port can report an arbitrary string, so this is untrusted input reaching a render surface. |
| user gesture to browser permission layer | The chip's click is the single event in the app that can cause a Web MIDI permission prompt, a fingerprintable capability grant. |
