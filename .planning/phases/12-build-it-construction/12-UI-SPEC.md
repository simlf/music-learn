# Phase 12 — UI Design Contract

> Visual and interaction contract for frontend phases. Generated by gsd-ui-researcher, verified by gsd-ui-checker.

**Mode:** Autonomous overnight run (user asleep). No `12-RESEARCH.md` exists; `12-CONTEXT.md` (D-01..D-09) is authoritative for engine/data decisions and is treated as locked. Every VISUAL/copy question CONTEXT.md left open is resolved below by grounding in the existing Print Shop system and the two closest structural precedents (`RecallSession`/`/recall`, `ScaleKeyboardDrill`/`/scales`) rather than inventing new patterns. Every discretionary call is marked **(Autonomous decision)** with its rationale so it can be challenged on read-back rather than silently assumed.

**Phase scope:** A new `/build` surface (BUILD-01..04): a target picker (chord root+quality chips, or scale tonic chips) that launches a one-target-at-a-time construction session — root pre-placed, next-interval-only prompts, tap-to-earn on a forced-2-octave `PianoKeyboard`, diagnostic wrong-tap feedback, a running formula strip, and a completion summary that both states the rule and confirms the fact was logged to the Phase 11 FSRS deck as that fact's `formula-build` mode card. Reuses every existing token, color, and shared component; introduces zero new colors, zero new spacing values, zero new type sizes.

**Sources:** `12-CONTEXT.md` (D-01..D-09, locked), `.claude/skills/spike-findings-music-learn/references/construction-mode.md` + `sources/007-construct-not-memorize/{index.html,README.md}` (the validated blueprint: flow, exact copy cadence, the 7-item pedagogical catalog, pacing, enharmonic-teaching insight), `.planning/PROJECT.md` (no em dashes, shop voice, local-first, scales stay major-only in v1), `src/app.css` (token contract, locked), `.claude/skills/sketch-findings-music-learn/references/drill-feedback.md` (wrong-fill gray convention, legend pattern), `src/lib/components/PianoKeyboard.svelte` + `keyboardLayout.ts` (gated-prop contract, `assignNotesToKeys`, octave-count math to extend), `src/lib/components/ScaleKeyboardDrill.svelte` (forced-2-octave horizontal-scroll pattern, transient wrong-flash timing, register-line convention — the closest precedent for a keyboard surface that must NEVER collapse to 1 octave), `src/lib/components/RecallSession.svelte` + `11-UI-SPEC.md` (session page-state machine, per-fact-kind prompt template convention, FSRS integration seam, "tap IS the answer" precedent), `src/routes/scales/+page.svelte` (mode-toggle-card structure, tonic chip row), `src/routes/+page.svelte` (root/quality-style picker precedent, starter-chip zero-friction pattern), `src/lib/theory/interval.ts` (`intervalBetween`, `IntervalInfo.long`/`.longFr`/`.semitones`, the base `phraseStep` extends), `src/lib/srs/{facts,deck}.ts` (fact catalog shape, `Mode` union, `recordGrade` seam this phase attaches `formula-build` mode to), `src/lib/theory/randomChord.ts` (`ROOTS`/`QUALITY_SUFFIXES`, the real chord-formula catalog — broader than the spike's 5-chord demo set), `src/lib/theory/scale.ts` (`MAJOR_SCALE_ROOTS`), `src/lib/components/{Button,ChordGlyph,IntervalChip,NoteLabel}.svelte` (components reused verbatim, only `PianoKeyboard` gains new props).

**Never** use vermilion or any of the seven interval-role tokens (root/second/third/fourth/fifth/sixth/seventh) for: the count-up hint toggle, the formula strip's unearned `?` placeholder chip, the wrong-pitch-class flash, or the wrong-octave branch. **This is the one hard rule this UI-SPEC enforces per the locked "texture not hue" constraint:** every named hue in `src/app.css` is already claimed by a chord/scale-degree role (fixed forever, DESIGN-02); Build-it introduces a brand-new urgency-adjacent state (a wrong tap, mid-construction) and must encode it WITHOUT touching hue. ### Wrong-tap key treatment (reused verbatim, no new tokens)

| State | Fill | Duration |
|-------|------|----------|
| Wrong pitch class | `--color-wrong` (white keys) / `--color-wrong-deep` (black keys) | 320ms transient flash, then reverts — identical constant to `ScaleKeyboardDrill`'s `wrongTimer` |
| Right pitch class, wrong octave | Same `--color-wrong` / `--color-wrong-deep` flash, same 320ms — **(Autonomous decision)** deliberately NOT a distinct color/texture from the wrong-pitch-class case. Both are "not the correct key to advance," and the copy alone (see Copywriting Contract) carries the pedagogical distinction; inventing a second wrong-treatment purely for octave errors would add visual grammar the sketch findings already rejected once (Sketch 001 Variant B/C, "extra visual grammar without enough added teaching value") |
| Correct | The note's own interval-color fill (`--color-root`/`--color-third`/etc.), `NoteLabel` shown, `.stamp-in` keyframe (240ms, `prefers-reduced-motion`-guarded, already in `app.css`) — identical to every other reveal surface | Permanent for the rest of the session (this key stays filled as an earned note) |

### Formula-strip chip states (new layout, no new tokens)

| State | Treatment |
|-------|-----------|
| Earned note | `IntervalChip` (role + short label, e.g. `R`, `m3`, `M3`) at full interval-color, immediately followed by the spelled letter in a small mono tag below it — identical markup family to Recall's/Lookup's existing formula-chip columns |
| Not yet earned (the very next target, and beyond) | A single dashed-border `?` placeholder chip: `1.5px dashed var(--color-faint)`, transparent fill, `?` glyph in `--color-muted`, Label role. Only ONE `?` chip is ever shown at a time (the next target); nothing renders for steps beyond it — the full remaining count is never spelled out, so the answer list is never implicitly revealed by "how many `?`s are left telling you the note count" being paired with visible interval labels beyond the next one |

| Step line (chords) | `Stack a {intervalLong} up from {lastLetter}.` e.g. `Stack a minor 3rd up from C.` (`intervalLong` from `phraseStep`) |
| Step line (scales) | `Take a {wholeOrHalf} step up from {lastLetter}.` e.g. `Take a whole step up from C.` (no semitone gloss for scales — "whole/half" already IS the count, restating it is noise) |
| WHY line (chords) | `That's the {role} of {symbol}.` e.g. `That's the third of Cm7.` |

| Count-up hint line (chords) | `{semitones} half step{s} up from {lastLetter}. Count it out.` — count only, never the destination letter (preserves desirable difficulty per D-08) |
| Count-up hint line (scales) | Not offered for scales — a whole/half step's count (1 or 2) is already fully stated by the step line itself; showing a hint toggle here would have nothing new to reveal |
| Correct-tap confirmation headline | Rotates through `['Nailed it.', 'Et voilà.', 'Bang on.', 'Spot on, mon ami.']`, same no-immediate-repeat picker convention Drills already uses (`pickVariant`), scoped to this component |
| Enharmonic teaching line (correct tap, only when notable) | `This key's usually called {commonName}, but {symbol} spells it {actualName} so the chord reads as a clean stack of {intervalWord}s.` — fires when the confirmed note's spelling is a double accidental (contains `♭♭`/`♯♯`) or one of the four natural-adjacent uncommon spellings (`C♭`, `F♭`, `E♯`, `B♯`); see Implementation Notes for the exact predicate boundary left to the planner |
| Wrong-pitch-class headline | Rotates through `['Not quite.', 'Close, but no cigar.', 'Not this time.']` — verbatim reuse of Drills' `WRONG_VARIANTS` |
| Wrong-pitch-class diagnostic line | `{n} half step{s} too {high or low}.` e.g. `2 half steps too high.` (singular "step" when `n === 1`) |

| Wrong-octave headline (fixed, not rotated — a specific teaching statement, not generic wrongness) | `Right note, wrong octave.` |
| Wrong-octave restatement | `You're stacking upward: try the next {letter} up.` |
| Retry policy | Unlimited retries per step, no attempt cap, no reveal/give-up affordance — matches "the learner must produce it" (D-08). Whether wrong attempts affect the eventual FSRS grade is a data-layer decision out of this UI-SPEC's scope (see Implementation Notes) |

## Layout Contract

### `/build` page structure

1. `<h1>Build It</h1>` (Heading role, matches every other page's h1 treatment)
2. Intro line (Body role)
3. Kind toggle row (`Chords` / `Scales`), `xl` gap below the intro line
4. Bordered card (`border-ink bg-paper-bright border-2 p-6`, same shared card convention every page uses) containing whichever state is active: picker, construction session, or completion summary

### Picker state, inside the card

- Chords: `Root` label + 12-chip row, `sm` gap, then `Quality` label + 8-chip row, `md` gap below the kind toggle
- Scales: single `MAJOR_SCALE_ROOTS` chip row, no secondary row
- Selecting the needed input(s) transitions in place to the construction session (no navigation, no separate card)

### Construction session, inside the card

Vertical stack, single column at every breakpoint (matches `/recall`'s "no bespoke landscape split" precedent — the feedback content here is text-only, no second keyboard to make room for):

1. Register line (`STEP {n} OF {total}`)
2. Target identity (`ChordGlyph` or `{tonic} major`)
3. Step line + WHY line (`sm` gap between them)
4. Count-up hint toggle, directly below the WHY line; its revealed line appears in place when tapped
5. Feedback zone: renders in place of / directly below the step+WHY block on a tap outcome (correct confirmation, wrong-pitch-class diagnostic, or wrong-octave line) — never a separate modal or route, `md` gap above
6. **Forced two-octave keyboard.** `PianoKeyboard` in `constructable` mode with `octaves={2}` passed explicitly (never left to self-measurement) — construction always needs the full 2-octave span (D-01/root pre-placed through a closing scale octave or a 7th chord's 7th), so it must NEVER collapse to 1 octave the way display/interactive `PianoKeyboard` usages do at narrow widths. Wrapped in the same horizontal-scroll affordance `ScaleKeyboardDrill` already established: an `overflow-x: auto` container with an explicit `min-width` floor (`15 × 44px` for the 15 white keys), auto-scrolling the root key into view on session start via `scrollIntoView({ inline: 'start' })`. `md` gap above.
7. Running formula strip: horizontal `flex-wrap` row of chips (earned notes + exactly one `?` placeholder), `md` gap below the keyboard

**Grading contract (the interaction spec behind "tap → confirm/correct → advance"):**
- A tap is graded **octave-strict**: correct only when it lands on the exact key the ascending-voicing placement (D-05) expects — both pitch class AND octave. This resolves the same duplicate-key ambiguity `ScaleKeyboardDrill` had to route around by NOT reusing `PianoKeyboard` (its chroma-only, any-octave-accepted grading collides with 2+ same-pitch-class keys on a 2-octave board) — construction mode's stricter octave requirement means every earned note maps to exactly one physical key, unambiguously, so `PianoKeyboard` itself CAN be safely reused per D-06.
- Right pitch class, wrong octave → the dedicated "Right note, wrong octave" branch (not the generic wrong-pitch-class diagnostic).
- Wrong pitch class entirely → the diagnostic branch (semitone distance + direction, computed from the tapped key's actual MIDI vs. the expected key's MIDI, not from chroma alone — direction requires real keyboard position).
- Correct → the key fills with its interval-color role, `NoteLabel` shows, `.stamp-in` fires, the formula strip's earned-chip count grows by one and its `?` placeholder shifts to the new next target, the confirmation headline (+ conditional enharmonic line) shows, then **the step auto-advances after ~650ms** (D-07's pacing — long enough that the confirmation is actually read, short enough to keep momentum). On the final step, the 650ms pause is followed by the transition into the completion summary instead of a new step.

### Completion summary, inside the card (replaces the construction session in place)

1. Heading
2. Rule statement
3. Finalized formula strip
4. Finalized display-mode keyboard
5. Status line
6. CTA row: `Build Another` (primary) + `Recall It Now` (ghost)

### 5-state page/session machine

Simpler than Recall's (no async gate up front — the theory engine's derivation is synchronous and local):

| State | Trigger | Renders |
|-------|---------|---------|
| `picking` | Default on `/build` load, and after `Build Another` | Picker (per kind) |
| `building` | A target was chosen | The construction session (steps above) |
| `feedback` | A tap just resolved (correct, wrong-pitch-class, or wrong-octave) | Same as `building`, with the feedback zone populated; auto-reverts to `building` (next step) or to `complete` (last step, correct) after the 650ms pace |
| `complete` | The target's final step was confirmed correct | Completion summary |
| *(no dedicated error state)* | The background `recordGrade` write to the FSRS deck fails | Best-effort, silent-catch, matches `RecallSession`'s `handleReveal` audio-failure pattern — a storage failure never blocks or alters the completion summary the user already sees; nothing to design here |

## Implementation Notes for Planner/Executor

- **Nav insertion:** add `{ href: '/build', label: 'Build' }` to `navLinks` in `src/routes/+layout.svelte`, positioned between `Drills` and `Recall` (see Design System table above).
- **`PianoKeyboard` prop additions are additive only** (gated-prop contract): `constructable`, `onConstructTap`, `flashWrongKey` are all optional and default to leaving the render byte-identical when omitted. Do not repurpose the existing `wrongLetters` prop for the construction wrong-flash — `wrongLetters` is a permanent-per-reveal, pitch-class-only (Set<letter>) semantic from Sketch 001's feedback keyboard; construction's wrong-flash is transient (320ms) AND octave-specific (a same-letter duplicate key elsewhere on the 2-octave board must NOT flash), which is a meaningfully different shape. Keep them separate props.
- **`construction.ts` state shape:** mirror `ScaleKeyboardDrillState`'s family (a `createConstructionState(target)`, an `expectedStep(state)` reader, a `gradeConstructionTap(state, letter, octave)` grader returning `{ outcome: 'correct' | 'wrong-pitch-class' | 'wrong-octave', ...diagnostic fields, state? }`) so `BuildSession.svelte`'s template can mirror `ScaleKeyboardDrill.svelte`'s structure closely — this is a strong structural precedent already proven in this codebase, not a new pattern to invent.
- **`phraseStep` extends `interval.ts`, not a component.** Per D-03, this keeps the chord/scale phrasing testable and shared (see the New/extended components table above for its exact signature).
- **Data-layer seams this UI-SPEC touches but does not resolve** (planner's job in the PLAN, not this file's):
  - `src/lib/srs/deck.ts`'s `Mode` type is currently `'formula'` only; it needs a `'formula-build'` member added (and the matching `CardRecordSchema` `mode` enum entry) for D-09's `recordGrade(card, rating, now)` calls to target the right (factId, mode) card.
  - `src/lib/srs/facts.ts` has no scale-level fact unit today — its `scale-degree` fact is per (tonic, degree) pair, which is the wrong grain for "build the whole scale." Building a scale target needs either a new `scale-formula` `FactKind` (tonic only, mirroring `chord-formula`'s shape) or an equivalent seam the planner designs; this UI-SPEC only requires that SOME factId exists per buildable scale target so `recordGrade` has somewhere to write.
  - Whether a step's wrong attempts (before eventual success) downgrade the FSRS rating for that fact, versus only first-attempt accuracy counting, is a scoring policy decision, not a visual one — the UI only needs to render the interaction (unlimited retries, no cap) documented above.
- **Chord-target catalog is the REAL fact catalog, not the spike's 5-chord demo set.** The picker offers the full `ROOTS × QUALITY_SUFFIXES` matrix (96 combinations, same catalog `facts.ts`'s `chord-formula` facts already enumerate), not just the spike's pedagogical `Cm7/F7/Bbmaj7/Bm7b5/Cdim7` five — those five remain useful only as a reference example set in this document's own reasoning, not as a UI restriction.
- **Scale targets stay major-only in v1** (`MAJOR_SCALE_ROOTS`, 12 tonics) — the spike's `D dorian` example proved the engine generalizes to modes, but modes are explicitly out of scope per `PROJECT.md` ("Minor scales, modes... NOT v1 requirements"). Do not surface a mode picker.
