<objective>
Extend `PianoKeyboard.svelte` with a third gated tap-driven mode, `constructable`, so Phase 12's construction session can reuse the app's one existing keyboard component instead of hand-rolling a second one (D-06): every key becomes tappable and reports its own letter+octave via `onConstructTap`, and a new `flashWrongKey` prop paints a transient, octave-specific wrong-fill on exactly the tapped key.

Purpose: D-06 explicitly requires reusing PianoKeyboard (not repeating ScaleKeyboardDrill's decision to hand-roll its own keyboard) — construction mode's octave-strict grading (every earned note maps to exactly one physical key, unambiguously) is precisely what makes that safe here, unlike ScaleKeyboardDrill's chroma-only grading which collides on a 2-octave board. Isolating and unit-testing the new gated props before BuildSession consumes them keeps the tricky mutual-exclusivity and octave-specific-flash logic under test in isolation from any session state machine.
Output: `PianoKeyboard.svelte`'s three new props (`constructable`, `onConstructTap`, `flashWrongKey`) and their passing test file, plus a proven zero-regression guarantee for every existing mode.
</objective>

<artifacts_this_phase_produces>
Symbols/props this plan adds to `PianoKeyboard.svelte`'s `Props` interface:
- `constructable?: boolean` — gates the new mode, mutually exclusive with `inspectable`, subordinate to `interactive`.
- `onConstructTap?: (letter: string, octave: number) => void` — fires on click/Enter/Space of ANY key while constructable is active; white keys report their plain letter, black keys report their sharp-spelling letter (matching `onPress`'s existing convention), both with their key-position octave (same `octaveForWhiteIndex`/`octaveForBlackAfterWhiteIndex` helpers already used elsewhere in the component).
- `flashWrongKey?: { letter: string; octave: number } | null` — when the letter+octave exactly match a rendered key's own reported identity, that key gets the wrong-fill CSS class; every other key (including same-letter duplicates at a different octave) is unaffected.

Downstream consumer (built in 12-04/05, not this plan): `BuildSession.svelte` wires `constructable`, `onConstructTap`, and `flashWrongKey` to `$lib/practice/construction`'s grading result.
