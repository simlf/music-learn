<objective>
Make PianoKeyboard responsive so it fits a phone without overflowing. Replace the fixed two-octave, `min-width: 660px` layout with a width-derived octave count (one octave on phone portrait, two octaves when at least the two-octave fit width is available), never rendering an interactive key below the 44px touch floor. Add pitch-class highlight wrapping so a chord that would run past the top of a one-octave span still shows every note in its interval color.

This is the core of the phase's user value: the keyboard overflow was the user's chief complaint from real phone testing. Every page that renders `PianoKeyboard` (lookup, drills, feedback reveal) inherits the fix through this one component (D-08).
