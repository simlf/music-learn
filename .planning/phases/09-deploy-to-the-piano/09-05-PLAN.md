<objective>
Add a minimal PWA so the app installs to the home screen and opens standalone, reclaiming the ~15% of landscape height that browser chrome eats (D-07). This is a web app manifest plus icons plus the `<head>` links — NO offline service worker this phase. Icon art, short name, and theme color are Claude's discretion within the Print Shop identity; keep colors to existing palette values.

Purpose: Standalone install is the difference between "a website I open" and "the app on my phone," and it directly serves the phone-first goal. This plan is independent of the keyboard work (disjoint files) so it runs in Wave 1.
Output: `static/manifest.webmanifest`, icons under `static/icons/`, `<head>` links in `src/app.html`, and a manifest-validity test.

Covers decision: D-07 (minimal PWA, no offline service worker).

**Deferred (documented, not built this phase):** PLAT-02 — Oracle-server HTTPS deployment — is handled by the user himself, outside these plans (CONTEXT.md Phase Boundary). Note that Add to Home Screen / standalone install and Web MIDI ultimately require the app to be served over HTTPS; that serving is the user's deferred deployment step, NOT a task here. Do not add deployment/HTTPS/docker tasks and do not claim PLAT-02.
</objective>

**As a** phone-first pianist, **I want to** add the app to my home screen and open it full-screen, **so that** it feels like a real app and I get the full viewport for the keyboard.
