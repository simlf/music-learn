# Phase 29 — UI Design Contract

> Visual and interaction contract for the Progress hub. Generated by gsd-ui-researcher, verified by gsd-ui-checker.

**Scope discipline:** This is a reuse-heavy consolidation phase. The Stats content, `RecallSession` + `RecallMap`, and the Songs management UI + `SongFilterToggle` are NOT redesigned — they are the source of truth and move as-is (REG-01). This contract only specifies what is genuinely new: the hub's own top-level layout chrome, its accent discipline, and where the song-filter toggle sits within the Songs section.

## Spacing Scale

Declared values (must be multiples of 4) — existing tokens, unchanged:

| Token | Value | Usage |
|-------|-------|-------|
| xs | 4px | Icon gaps, inline padding |
| sm | 8px | Compact element spacing (e.g. tab-button gap) |
| md | 16px | Default element spacing, page padding |
| lg | 24px | Section padding |
| xl | 32px | Layout gaps |
| 2xl | 48px | Major section breaks |
| 3xl | 64px | Page-level spacing |

Exceptions for this phase: none. The top-level tab bar uses `gap-2` (`--spacing-sm`, 8px) between buttons, matching `/recall`'s existing mode-toggle spacing exactly. Touch targets on the tab buttons stay ≥44px via `Button.svelte`'s existing `min-height`/`min-width` (no new exception needed).

## Color

| Role | Value | Usage |
|------|-------|-------|
| Dominant (60%) | `--color-paper` (#f2ecdd) | Page background |
| Secondary (30%) | `--color-paper-bright` (#faf6ea) + `--color-ink` 2px borders | Cards, the section panel wrapping each active tab's content (mirrors `/recall`'s `border-ink bg-paper-bright border-2` panel) |
| Accent (10%) | `--color-vermilion` (#c8502e) | See "Accent reserved for" below — unchanged from existing Stats/Recall/Songs usage, not expanded |
| Destructive | none new | Song delete keeps its existing inline two-step text-link confirm (not a vermilion/red destructive button) — unchanged from `/songs` today |

**Accent reserved for (explicit list — this phase changes nothing here, it only keeps discipline as the hub gets busier):**

1. The **selected top-level hub tab** (Stats | Recall | Songs) — `Button variant="primary"`, unselected tabs stay `variant="ghost"`. Exactly the same pattern as the existing `/recall` Review|Map toggle and `/scales`/`/learn` tier toggles.
2. The **selected nested Recall toggle** (Review | Map) — unchanged, reused verbatim from `/recall`.
3. **Primary CTAs already defined by Stats/Songs**, reused as-is: Save token, "Practice Now" (streak CTA), "Drill these" (danger-cards seed handoff), Add-song submit, delete-confirm button, tier-level toggle's active tier.
4. The tier-progress "practiced" fill meter in Stats (existing `--color-vermilion` background fill) — unchanged.

**Explicitly NOT accent:** section headings, tab labels in their unselected state, card borders/backgrounds, chart bars in `RecallMap`/calibration (those already use the interval-color language — root/third/fifth/seventh — or the wrong-answer grays, never vermilion, per the existing DESIGN-02 contract). The hub composing three heavy parts onto one surface must not read as "more red" than any one part did alone — vermilion count on screen at any time should be low (one selected top-level tab + at most one selected nested toggle + zero-or-one visible primary CTA).

## Layout Contract (new for this phase)

**Structure:** a top-level, non-scrolling tab set of exactly three tabs — **Stats | Recall | Songs** — rendered as `Button variant="primary"|"ghost"` + `aria-pressed`, `role="group"`, byte-for-byte the same pattern as `/recall`'s existing Review|Map toggle (see `src/routes/recall/+page.svelte` lines 38-60). Only the active tab's section is mounted/visible at a time — this is a **switch, not a scroll-anchor list**. Rationale, binding for the executor:

1. **Phone-first glanceability.** Stats + Recall + Songs concatenated as one long scroll would put Songs several screens below the fold on a phone; a tab switch keeps every section a single tap away and matches PROG-01's "reachable from the one Progress surface" requirement without forcing a scroll-heavy page.
2. **The Recall review-action-dock is state-coupled, not just visual.** `/recall` sets `data-review-dock` on its own `<main>` only while `mode === 'review'`, which drives extra fixed-bottom padding co-ordinated with `RecallSession`'s self-measured docked action bar (`--review-dock-clearance`, `src/app.css`). If Stats/Recall/Songs were all rendered simultaneously in one scrolling page, that dock (fixed above the phone tab bar) would remain visible while the user is scrolled into the Stats or Songs section — confusing and wrong. A tab switch that unmounts non-active sections keeps this coupling exactly as correct as it is today, with zero new logic: gate the hub's own `<main data-review-dock>` attribute on `activeTab === 'recall' && recallMode === 'review'` instead of `/recall`'s current unconditional `mode === 'review'`.

**Tab order (phone-first landing):** **Stats first** — it is the existing `/progress` default landing and the most glanceable, at-a-glance content (streak hero, weakest spots, accuracy). Recall second (the deeper practice-review workflow). Songs third (management/config, least frequently visited day-to-day).

**Recall's internal structure stays nested, not flattened.** Do NOT promote Review/Map to two of the hub's own top-level tabs (i.e. do not make it Stats | Review | Map | Songs). Reasons:
- Keeps the top-level tab count at 3, matching the "minimal" instruction in 29-CONTEXT.md and avoiding a 4-wide tab row that would wrap or shrink on narrow phones.
- Preserves `/recall`'s own toggle component verbatim (extract as `RecallPanel.svelte` per 29-CONTEXT.md's DRY guidance) with zero internal changes — the nested Review|Map toggle inside the Recall tab is byte-identical reuse, not a new pattern.
- Matches 29-CONTEXT.md's explicitly recommended fallback: "Stats | Recall | Songs with Recall keeping its internal Review|Map."

**Songs section internal layout:** the `SongFilterToggle` sits at the **top of the Songs tab's content**, above the song list and the add/preset form — exactly where it sits on `/songs` today (immediately after the section's own heading, before the song rows). No new placement decision is being made; this is REG-01 verbatim reuse. It is called out explicitly because Songs is now one of three sibling tabs rather than a whole page, and the toggle's prominence (first thing visible on entering the Songs tab) must not be lost in extraction — it is the sole writer of the global `music-learn:song-filter` preference that Practice and Recall both read.

**Section chrome:** each tab's content renders inside the same panel treatment already used by `/recall` (`border-ink bg-paper-bright border-2`, padding `px-2 py-6 sm:px-6`) so the three sections read as one consistent hub rather than three different visual languages stitched together. A section does not repeat its own page's old `<h1>` — that becomes the hub's shared page title; each section keeps only its own internal headings (e.g. Stats' streak hero heading, Songs' "Presets" `<h2>`) unchanged.

**Hub page title:** one shared `<h1>` at the top of `/progress` (e.g. "Progress" — existing `progress.page.title` or a new hub-level title key), replacing the three separate per-route `<h1>`s. Each absorbed section's own former `<h1>` is dropped in favor of this one hub title, consistent with how `/learn` dropped Theory/Explore's separate page titles in favor of one `learn.page.title`.
