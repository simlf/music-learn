# Phase 1 — UI Design Contract

> Visual and interaction contract for frontend phases. Generated by gsd-ui-researcher, verified by gsd-ui-checker.

**Phase scope:** Establish the "Print Shop" visual identity, the interval color language, and a `/showcase` route that renders any supported chord (theory engine output) in the full Print Shop style with the colored keyboard diagram. No drills, no lookup UX polish yet (Phases 2–3). This contract defines app-wide tokens that all later phases inherit.

**Sources:** `.planning/design/design-hybrid.html` (variant B "Print Shop" — chosen direction), `.planning/design/design-keys.html` (key-color tests), REQUIREMENTS.md DESIGN-01/DESIGN-02, STATE.md decisions, user confirmation 2026-07-12 (interval colors, no component library, `/showcase` route, system fonts).

## Spacing Scale

Declared values (must be multiples of 4):

| Token | Value | Usage |
|-------|-------|-------|
| xs | 4px | Inline gaps (chord glyph to solfège sub-label, chip internal padding) |
| sm | 8px | Gaps between sibling labels, button icon gaps |
| md | 16px | Default element spacing, card internal padding, button padding-x |
| lg | 24px | Section padding inside the showcase card |
| xl | 32px | Gaps between major blocks (chord header / keyboard / interval readout) |
| 2xl | 48px | Page top/bottom padding (desktop) |
| 3xl | 64px | Max page-level spacing (large screens) |

Exceptions:
- **2px borders** (DESIGN-01 "heavy 2px borders") and **1.5px keyboard key borders** — border widths, not spacing.
- **3px offset shadows** (buttons, misregistered chord glyph shadow) — decorative offsets, not spacing.
- **44px minimum touch target** on any future interactive key/button (applies from Phase 3; declared now so keyboard key width is sized ≥44px on mobile from the start).

## Typography

Exactly 4 sizes, 2 weights (400, 700):

| Role | Size | Weight | Line Height | Family |
|------|------|--------|-------------|--------|
| Body | 16px | 400 | 1.5 | UI sans |
| Label (data/mono) | 12px | 700 | 1.4 | Mono (Courier New) — streak counters, solfège sub-labels, interval formulas, uppercase task labels with `letter-spacing: 0.14em` |
| Heading | 20px | 700 | 1.2 | UI sans — section headings, brand mark (uppercase, `letter-spacing: -0.02em`) |
| Display (chord glyph) | 56px | 700 | 1.05 | Serif (Georgia) — chord symbols only; quality suffix as superscript at 24px |

Notes:
- Note letters on keyboard keys render at Label size bounds (10–12px bold sans) with solfège at 9–10px below — treated as part of the Label role, not extra sizes.
- Never use weights other than 400 and 700. Emphasis via weight, color, or case — not additional weights.

## Color

| Role | Value | Usage |
|------|-------|-------|
| Dominant (60%) | `#f2ecdd` (paper) | Page background, card surfaces, primary-button text |
| Secondary (30%) | `#faf6ea` (bright paper) + `#221e17` (ink) | White keyboard keys, input fields (`#faf6ea`); all borders, black keys, text, inverted chips like streak/feedback bars (`#221e17`) |
| Accent (10%) | `#c8502e` (vermilion) | See reserved-for list below |
| Muted text | `#7d7462` | Secondary copy, solfège sub-labels on paper ground |
| Faint labels | `#9a907f` | Note labels on unhighlighted keys |
| Destructive | none in Phase 1 | No destructive actions this phase; when needed later, use ink-on-vermilion inverted treatment, never a new red |

Accent (vermilion `#c8502e`) reserved for — exhaustive list:
1. Primary button background
2. Misregistered print shadow behind chord glyphs
3. Root interval color (see below)

Never use vermilion for: links, focus rings, borders, headings, hover states, or "all interactive elements". Focus rings use ink `#221e17` (2px offset outline).

### Interval Color Language (DESIGN-02 — app-wide, fixed forever)

| Interval role | Color | Hex | Text on fill |
|---------------|-------|-----|--------------|
| Root | Vermilion | `#c8502e` | `#f2ecdd` (letter `#ffffff` bold) |
| 3rd | Verdigris | `#3e7d6b` | `#dff0e8` (letter `#ffffff` bold) |
| 5th | Muted tan | `#a89a7f` | `#221e17` |
| 7th | Mustard | `#f0c948` | `#221e17` |

Rules:
- These four colors apply identically everywhere: highlighted keyboard keys, interval-formula chips, lesson diagrams (Phase 7), drill feedback (Phase 3). They are semantic tokens (`--color-root`, `--color-third`, `--color-fifth`, `--color-seventh`), not decorative.
- Triads (no 7th) simply omit mustard — no re-mapping.
- Interval colors sit outside the 60/30/10 budget: they are data encoding (like chart colors), used only on keyboard highlights and interval chips, never on chrome/UI surfaces.
- Contrast note: mustard and tan fills take ink text; vermilion and verdigris take paper/white text (verified against mockups).

## Copywriting Contract

Phase 1 surface is the `/showcase` route: a chord symbol input + rendered result. Tone: terse, print-shop-poster confidence; uppercase mono for status lines (matches `OK — ANY INVERSION COUNTS` mockup register).

| Element | Copy |
|---------|------|
| Page title / brand | `MUSIC LEARN` (uppercase brand mark), route heading `Chord showcase` |
| Primary CTA | `Show chord` |
| Input placeholder | `Type a chord — Cm7, F♯ø7, B♭maj7…` |
| Empty state heading | `No chord yet` |
| Empty state body | `Type a symbol like Cm7 and press Show chord to see its notes in ink and color.` |
| Error state (unparseable symbol) | `UNRECOGNIZED SYMBOL — try Cm7, C-7, F♯ø7, or B♭maj7` (rendered in the inverted ink bar, mustard mono text; non-blocking — previous result stays visible) |
| Alias confirmation line | When input was an alias, show `Cm7 = C-7 = Cmin7` in muted mono under the chord glyph (proves THEORY-02 visually) |
| Interval formula readout | `R + m3 + P5 + m7` as IntervalChips with dual-named notes beneath |
| Destructive confirmation | none — Phase 1 has no destructive actions |

## Implementation Notes for Planner/Executor

- Define all tokens as CSS custom properties in the Tailwind 4 CSS-first config (`@theme` block): `--color-paper: #f2ecdd`, `--color-paper-bright: #faf6ea`, `--color-ink: #221e17`, `--color-vermilion: #c8502e`, `--color-mustard: #f0c948`, `--color-verdigris: #3e7d6b`, `--color-tan: #a89a7f`, `--color-muted: #7d7462`, `--color-faint: #9a907f`, plus the four semantic interval aliases.
- `border-radius: 0` globally (sharp corners are identity, DESIGN-01) — set Tailwind radius tokens to 0 rather than fighting per-component.
- The misregistered shadow duplicate must be `aria-hidden="true"` and excluded from text selection (`user-select: none`).
- Solfège uses French spellings with accents: Do, Ré, Mi, Fa, Sol, La, Si (THEORY-04; user is French).
- Accidentals render as proper glyphs (♯ ♭ ø °), never `#`/`b` in display text (input accepts both).
- Keyboard must render enharmonically correct labels from the theory engine (F♯m7 shows C♯, not D♭ — THEORY-03); the keyboard component takes spelled note names, not MIDI numbers, for labels.
