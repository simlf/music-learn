<objective>
Add a native SvelteKit service worker (`src/service-worker.ts`) that makes the app load offline and instantly on repeat visits, and satisfies the "active service worker over HTTPS" precondition for Android/Chrome installability. Precache the immutable build assets, the small static files, and the prerendered route HTML on install; exclude the heavy Salamander piano samples from install precache and runtime-cache them on demand instead; clean stale caches on activate; serve cache-first with a network fallback. All caching-decision logic that can be unit-tested lives in a pure `src/lib/pwa/precache.ts` module so it runs under Vitest without SW globals.

Purpose: PWA-01 — offline app-shell caching, the substantive core of the Installable PWA phase, built on SvelteKit's `$service-worker` module with NO new runtime dependency.

    Create `src/service-worker.ts` following SvelteKit's documented `$service-worker` pattern (SvelteKit 2.69.2 auto-registers this file in the production client build; leave `kit.serviceWorker.register` at its default — do NOT edit svelte.config.js). Start the file with `/// <reference types="@sveltejs/kit" />`, import `{ build, files, prerendered, version }` from `$service-worker`, and cast self via `const sw = self as unknown as ServiceWorkerGlobalScope;` so `npm run check` stays at 0 errors. Import `installPrecacheList` and `cacheName` from `$lib/pwa/precache` and `SALAMANDER_BASE_URL` from `$lib/audio/samples`. Compute `const CACHE = cacheName(version);` and `const PRECACHE = installPrecacheList(build, files, prerendered);` and `const PRECACHE_SET = new Set(PRECACHE);`.

    install: `event.waitUntil` opening `CACHE` and `cache.addAll(PRECACHE)` (build + small files + prerendered; samples excluded by the helper). Do NOT call skipWaiting here — a new worker must wait so Plan 03 can prompt the user before it takes over (no silent mid-session reload).

    activate: `event.waitUntil` deleting every cache key `!== CACHE` (stale prior-version cleanup keyed by version), then `sw.clients.claim()`.

    fetch: ignore (return early) any request whose method is not GET. For same-origin requests only:
      - If the URL pathname is in `PRECACHE_SET`, serve cache-first (return the cached immutable asset).
      - If `isSampleAsset`-style match (pathname includes SALAMANDER_BASE_URL): runtime-cache-on-demand — try the cache first; on miss, fetch from network, and if the response is a same-origin 200 (not opaque/error), `cache.put` a clone before returning it (so offline playback works after first use; the synth fallback already covers offline-before-first-play).
      - For navigation requests (`request.mode === 'navigate'`): try the network, and on failure fall back to the cached prerendered page for that URL, then to the cached app-shell root `/` — so routes open offline.
      - Otherwise: network-first, and on network failure fall back to any cache match.
      Guard every `cache.put`: only cache successful same-origin GET 200 responses; NEVER cache non-GET, cross-origin, opaque, or non-200/error responses (T-22-01).

    message: add a `message` listener — when `event.data?.type === 'SKIP_WAITING'`, call `sw.skipWaiting()`. This is the exact contract Plan 03's update flow posts to; keep the shape `{ type: 'SKIP_WAITING' }` literally.

    Do NOT place any string that an acceptance criterion negative-greps for inside comments. Keep comments describing intent (offline shell, sample exclusion, version-keyed cleanup).

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| network → SW cache | The SW intercepts every fetch; a cached bad/opaque response would be served to all future requests. |
| client → SW (postMessage) | The update flow posts a control message the SW acts on. |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-22-01 | Tampering | service-worker.ts fetch handler | medium | mitigate | Only cache same-origin GET responses with status 200; never cache opaque/cross-origin/error responses or non-GET requests. |
| T-22-02 | Denial of Service | runtime sample cache | low | accept | Sample set is a finite 30-file same-origin bundle (~1.9MB); cache growth is bounded, no attacker-controlled URLs enter the cache. |
| T-22-03 | Elevation of Privilege | SW message listener | low | mitigate | Act only on the exact `{ type: 'SKIP_WAITING' }` shape; skipWaiting merely activates the already-installed waiting worker (benign, same-origin only). |
</threat_model>
