<objective>
Complete the LOOK-01 error experience: a minimal single-candidate "did you mean" suggestion. On unrecognized input, run a small heuristic against the supported chord matrix; if exactly one confident candidate emerges, the error bar shows one tappable inline suggestion in the print-shop clerk voice, and tapping it stamps that chord. If nothing confident emerges, fall back to the existing rotating hints. This promotes the Phase 1 deferral into a shipped, non-blocking helper that never scolds and never auto-corrects.

Purpose: Turn "unrecognized" from a dead end into a one-tap recovery for the common near-misses a returning pianist will type at speed, satisfying success criterion 3 (clear, non-blocking message rather than a wrong answer) at full quality.
Output: A pure `didYouMean.ts` heuristic with tests, `suggestionHints`/`pickSuggestionHint` copy in `hints.ts`, and the lookup page's error branch wired to render and act on the suggestion.
</objective>

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| user text input -> didYouMean | Untrusted free-text near-misses cross into the heuristic, which computes a candidate symbol. |
| candidate symbol -> showChordFromSymbol -> spellChord | The suggested candidate re-enters the parser on tap; it is drawn from the vetted supported matrix. |

## STRIDE Threat Register

ASVS level 1, block on high. Single-user, client-side static app: no server, no auth.

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-02-07 | Denial of Service | didYouMean Levenshtein over arbitrary-length input | low | mitigate | The heuristic runs against a fixed 96-entry candidate set and only compares short quality tokens; input is trimmed and the root check short-circuits non-matching roots, so cost is bounded regardless of input length. didYouMean is total (returns null, never throws) preserving the non-blocking render path. |
| T-02-08 | Spoofing | suggested candidate that does not actually parse | medium | mitigate | Candidates are constructed only as root+suffix over the proven 12x8 matrix (every entry is a symbol spellChord recognizes per reference-chords.test.ts), so a tapped suggestion can never stamp an unrecognized/wrong chord; the ambiguous-tie -> null rule prevents low-confidence wrong guesses. |
| T-02-09 | Tampering | suggestion token text rendered in the error bar | low | accept | The candidate is a canonical matrix symbol echoed via Svelte auto-escaping (no {@html}); no injection surface for this single-user local app. |
</threat_model>
