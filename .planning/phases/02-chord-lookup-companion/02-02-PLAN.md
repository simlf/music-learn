<objective>
Layer mid-song ergonomics onto the working lookup page: a recent-lookups chip row (last 5 distinct, tap to re-stamp, persisted in localStorage), ♯/♭ glyph helper buttons for phone typing, and autofocus + type-over-select input behavior. Real lead sheets repeat the same 4-6 chords, so re-tapping beats re-typing; phone keyboards make accidental glyphs and focus management the difference between usable and frustrating at the piano.

Purpose: Make LOOK-01 genuinely usable mid-song at the piano on a phone, not just functionally correct.
Output: A pure `recentLookups.ts` persistence module with tests, a `RecentChipRow.svelte` component, and the lookup page wired for recents + helpers + focus behavior.
</objective>

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| localStorage <-> app | Persisted recent-lookup array crosses between the browser store and the app; the store is user-controllable and may be corrupt/absent. |
| user text/glyph input -> input value | Untrusted text plus glyph insertions build the symbol string before it reaches spellChord. |

## STRIDE Threat Register

ASVS level 1, block on high. Single-user, client-side static app: no server, no auth.

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-02-04 | Tampering | localStorage recent-lookups value | low | mitigate | getRecentLookups validates the parsed value is a string array and returns [] on malformed/corrupt data inside a try/catch; a hand-edited or corrupt store never crashes the page (verified by the malformed-value test). |
| T-02-05 | Denial of Service | localStorage unavailable / quota exceeded | low | mitigate | All localStorage access is wrapped in try/catch; read failures degrade to an empty list and write failures are no-ops, so the lookup loop keeps working with recents simply disabled. |
| T-02-06 | Tampering | recent chip symbols rendered in markup | low | accept | Chip text is a resolved chord symbol echoed via Svelte auto-escaping text interpolation (no {@html}); stored values only ever originate from spellChord's canonical symbol, so no injection surface for this single-user local app. |
</threat_model>
