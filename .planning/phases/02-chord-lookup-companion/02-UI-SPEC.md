# Phase 2 — UI Design Contract

> Visual and interaction contract for frontend phases. Generated by gsd-ui-researcher, verified by gsd-ui-checker.

**Phase scope:** Productize the `/showcase` engine test into the app's primary surface. New surfaces this phase: persistent masthead/nav shell (`+layout.svelte`), the lookup page as app home (`/`), the input row with ♯/♭ helper buttons, the recent-lookups chip row, and a "did you mean" suggestion inside the existing error bar. All tokens, interval colors, typography, and core components are LOCKED by `01-UI-SPEC.md` / `src/app.css` and are extended here, never redefined.

**Sources:** `.planning/phases/02-chord-lookup-companion/02-CONTEXT.md` (all decisions locked, autonomous run), `.planning/phases/01-print-shop-foundation-theory-core/01-UI-SPEC.md` (locked visual contract), `.planning/phases/01-print-shop-foundation-theory-core/01-CONTEXT.md` (D-01..D-12, tone/motion/error-state rules), `src/app.css` (implemented token contract), `src/routes/showcase/+page.svelte` (working composition this phase productizes).

## Spacing Scale

Declared values (must be multiples of 4) — identical to Phase 1, no new tokens needed:

| Token | Value | Usage |
|-------|-------|-------|
| xs | 4px | Inline gaps (chip internal padding, helper-button glyph padding) |
| sm | 8px | Gaps between input row elements, chip row gaps, nav link gaps |
| md | 16px | Default element spacing, masthead row padding, input/button padding-x |
| lg | 24px | Section padding (masthead horizontal padding desktop, card sections) |
| xl | 32px | Gaps between major blocks (input row / recent chips / chord result / keyboard) |
| 2xl | 48px | Page top/bottom padding (desktop) |
| 3xl | 64px | Max page-level spacing (large screens) |

Exceptions (carried from Phase 1, still apply):
- 2px borders (masthead bottom border, input border, button borders) and 1.5px keyboard key borders.
- 3px offset shadows (buttons, misregistered chord glyph shadow).
- 44px minimum touch target — now load-bearing this phase for the ♯/♭ helper buttons and recent chips, not just a future-proofing note.

New exception:
- **Mobile-portrait above-the-fold budget (conditional, explicit fallback):** on viewport width ≤375px and height ≤667px (iPhone SE baseline) with a recent-chip row present: if the stack height of masthead + input row + recent chips + chord glyph + keyboard exceeds the viewport height, reduce the recent-chip row's top margin from `md` (16px) to `sm` (8px). Otherwise use the standard `md` (16px) top margin. This is the only conditional spacing value in this spec. Keyboard size and type sizes are never trimmed; all other spacing values are unconditional.

## Typography

Exactly 4 sizes, 2 weights (400, 700) — unchanged from Phase 1, no new roles:

| Role | Size | Weight | Line Height | Family |
|------|------|--------|-------------|--------|
| Body | 16px | 400 | 1.5 | UI sans |
| Label (data/mono) | 12px | 700 | 1.4 | Mono — nav links, recent chips, helper-button glyphs, error bar, "did you mean" suggestion |
| Heading | 20px | 700 | 1.2 | UI sans — masthead brand mark, section headings |
| Display (chord glyph) | 56px | 700 | 1.05 | Serif — chord symbol result, unchanged |

Notes:
- Masthead brand mark and nav links both live inside the Heading/Label size bounds already declared — no new size is introduced for navigation chrome.
- Helper button glyphs (♯/♭) render at Body size (16px) inside a 44px square button, not Label size — they need to be legibly large as tap targets, matching the visual weight of the accidental glyphs shown elsewhere (chord glyph, keyboard labels).

## Layout Contract (new this phase)

Vertical stack, top to bottom, applies to both desktop and mobile portrait (mobile just compresses spacing per the above exception, same order):

1. Masthead (brand + nav)
2. Page heading (`Chord lookup`) — Heading role, `md` top margin below masthead
3. Input row (input + ♯/♭ helpers + Stamp button)
4. Recent-chips row (only if history exists in `localStorage`; absent otherwise)
5. Error bar (only if the most recent submit was unrecognized; non-blocking, does not replace item 6)
6. Chord result: glyph + alias line + "Hear it" + keyboard diagram + interval-formula chips (unchanged internal composition from `showcase`, reused as-is per 02-CONTEXT.md's extraction guidance)

On mobile portrait, items 1 through 4 (or 1-3 if no recent chips yet) plus the chord glyph and keyboard (start of item 6) must fit above the fold. The interval-formula chips row may sit just below the fold since it's a secondary confirmation, not required for the "see the notes" primary loop.

Input behavior contract (from 02-CONTEXT.md, restated here as the visual/interaction spec):
- Renders only on explicit submit (Enter, Stamp click, starter-chip click, or recent-chip click). No live-render-as-you-type.
- Autofocus on page load.
- After a result renders, focus returns to the input with its content selected (type-over ready).
- Accepts lowercase, ASCII `#`/`b`, and glyph `♯`/`♭`; trims whitespace. Normalization happens at the UI boundary (page-level function), not inside `spellChord`.
- Last successful result stays rendered through a failed subsequent submit; only the error bar changes.
