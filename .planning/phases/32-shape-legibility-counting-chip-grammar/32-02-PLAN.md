## Ground truth (verified against spellChord + stackedThirdsFor)

- `IntervalRole` (src/lib/theory/types.ts) has SEVEN values: root, second, third, fourth, fifth, sixth, seventh. CountingChipRow currently styles only root/third/fifth/seventh.
- Tokens for the missing three ALREADY EXIST in src/app.css: `--color-second`/`--color-on-second`, `--color-fourth`/`--color-on-fourth`, `--color-sixth`/`--color-on-sixth`. Sibling `IntervalChip`/`ScaleDegreeStrip` already tint all seven.
- Real drill-pool chords (verified this plan):
  - `Csus4` -> roles root,fourth,fifth | gaps `+P4 +M2` (both non-third)
  - `C6` -> roles root,third,fifth,sixth | gaps `+M3 +m3 +M2` (last non-third)
  - `Cmaj9` -> roles root,third,fifth,seventh,second | gaps all thirds (exercises `second` tint, no neutral gap)
  - `C13` -> roles root,third,fifth,seventh,second,sixth | gaps `+M3 +m3 +m3 +M3 +P5` (last non-third)
- The tone `role` class is ALWAYS present in markup (`class="tone-chip {tone.role}"`); the WR-01 defect is purely MISSING CSS, so its objective gate is a source assertion for the three new style rules (a DOM classList check cannot detect the missing tint under jsdom).
- The neutral-gap fix IS behavioral: `gapModifier()` today returns `''` for non-thirds -> a DOM test asserting the new neutral modifier class goes RED pre-fix / GREEN post-fix.
- Old grey line (removed in commit 769afa7): a `<p data-testid="chord-drill-shape" class="... font-mono uppercase text-muted">` rendering `{targetQuality}: {stackedThirdsPattern}` where the pattern was gap labels joined by ` · ` (U+00B7 middot), e.g. Cm7 -> `m7: m3 · M3 · m3`. The new CountingChipRow NEVER emits a middot-joined run, so absence of that ` · ` pattern is the real removal fingerprint.
