<objective>
Fix the over-generous mastery criterion (improvement I-01, confirmed defect observed during v2.0 verification: a single Good grade flipped a card to "Mastered"). Grounded in successive-relearning research (Rawson and Dunlosky): durable mastery requires correct retrieval across multiple separate sessions/days, not one success in one sitting. Introduce a distinct-calendar-day correct-review counter and only report a card "mastered" once it has been recalled correctly on at least 2 separate days.
</objective>

<tasks>

<task number="1" tdd="true">
<name>masteryDayCount field, schema default, and recordGrade day-counter</name>
<action>
Add `masteryDayCount: number` to CardRecord and CardRecordSchema (z.number().int().min(0) with a legacy default of 0 so existing IndexedDB records load without throwing). In recordGrade, when the committed grade is correct (Rating.Good or Rating.Easy): if the card has never been mastery-counted, or the previous last_review falls on a DIFFERENT local calendar day than now (compare getFullYear/getMonth/getDate, local not UTC, per the Phase 08 clientDate convention), increment masteryDayCount by 1; otherwise leave it unchanged. A Rating.Again or Rating.Hard grade never increments masteryDayCount. New cards created via createEmptyCard start at masteryDayCount 0.
Write failing tests first: (a) a first correct grade sets masteryDayCount to 1; (b) a second correct grade on the SAME day leaves it at 1; (c) a correct grade on a later day raises it to 2; (d) an Again grade does not increment; (e) a legacy record with no masteryDayCount field loads via the schema and defaults to 0.
</action>
</task>

<task number="2" tdd="true">
<name>deriveCellState mastered gate</name>
<action>
Change deriveCellState so a card reports 'mastered' only when card.state === State.Review AND card.masteryDayCount >= 2 (and it is not currently due, preserving the existing due-takes-priority rule). A State.Review card with masteryDayCount < 2 reports 'weak'. All other branches (not-yet-seen, due, lapsed->weak) unchanged. Update deck.test.ts's mastery assertions and RecallMap tests so a single-grade card is 'weak' and a 2-distinct-day card is 'mastered'. Confirm no RecallMap visual/structural regression (legend and columns unchanged; only which cells qualify as mastered changes).
Run `npx vitest run` and `npm run check`; both must be green.
</action>
</task>

</tasks>
