## Scope Decisions (autonomous — resolved without user input)

These are the judgment calls CONTEXT.md left open ("include if cheap, else defer," "Claude's discretion"-shaped gaps). Each is resolved and justified so the checker and planner never have to re-litigate them.

1. **Mode D (notes→symbol) is deferred, not built.** CONTEXT D-05 makes it conditional ("if built"); the task's own surface list (1-5 above) never mentions it. Deferring keeps this phase's scope to exactly RECALL-01..03. `deck.ts`'s `Mode` union gains `'see-play'` and `'hear-name'` only, not `'notes-symbol'`. The recall map gets 3 new columns (Build, Play, Name), not 4.
2. **Mode A and Mode B are chord-formula facts only** (`factKind: 'chord-formula'`), never `interval-size` or `scale-degree`. Justification: the reused grading primitives — `matchChord` (takes a `ChordResult`) and `pickDistractors` (takes a chord symbol, guarantees same-root) — are chord-shaped functions with no interval/scale-degree equivalent. CONTEXT's own D-03/D-04 describe chord grading exclusively ("hear the CHORD," "matchChord chroma logic"). Building new grading/distractor logic for intervals or scale degrees would exceed "wires existing pieces" scope discipline. The recall map's new `see-play`/`hear-name` columns therefore render a genuine cell only on chord-formula rows (see Recall Map Extension).
3. **Mode C (`formula-build`) inherits its existing chord+scale scope unchanged.** Phase 12's `createChordConstruction`/`createScaleConstruction` already cover both; Phase 13 does not extend or restrict this.
4. **Grading signal per new mode is a binary correct/incorrect auto-rating, never a manual 4-button grade.** Mode A: `matchChord(...).correct ? Rating.Good : Rating.Again`. Mode B: `choice === fact.symbol ? Rating.Good : Rating.Again`. Justification: "Grade-from-answer-time heuristic" is explicitly deferred in CONTEXT, and a manual grade picker on TOP of an already-graded keyboard-check or a low-stakes ear guess would add friction the spike's design intent (fast, felt rotation) argues against. The existing `formula` mode keeps its manual 4-button grade unchanged (nothing about that reveal-only card's contract changes).
5. **Mode A pacing: manual "Next," not auto-advance.** The merged feedback keyboard (interval-color reveal + wrong-gray + ✕) is the app's single richest teaching moment for a miss; rushing past it with a timer would undercut it. Mirrors Drills' own construction-branch precedent (explicit Next button, no timer).
6. **Mode B pacing: auto-advance after 650ms**, reusing BuildSession's exact `feedbackTimer` constant. Justification: CONTEXT explicitly demotes Mode B ("lowest rotation weight," "never gates") — it should be the fastest, lowest-friction mode in the rotation, and 650ms is an established, already-proven pacing constant in this codebase (not a new number).
7. **Mode C, embedded in Recall, replaces its own exit buttons.** Standalone `/build`'s completion screen shows "Build Another" / "Recall It Now" — neither makes sense mid-queue. Embedded in RecallSession, Mode C's completion beat keeps the heading, rule statement, formula strip, and keyboard verbatim, but swaps those two buttons for a single primary "Next" that advances the recall queue (same action/copy as Mode A's Next). BuildSession's own "SAVED TO RECALL · FORMULA-BUILD MODE" status line is suppressed in this embedding (redundant self-reference — the surface already IS Recall).
8. **Every mode in the rotation gets a mode-signal chip**, including the pre-existing `formula` mode (which had none before this phase). Justification: legibility of "multi-modal encoding" only exists once there is more than one path to compare; adding the label to `formula` too (not just the 3 new modes) is required for the family to read as one system, not three new modes plus an unlabeled old one.
9. **RevealInsight is reused for Mode B, never for Mode A.** Mode B picks a chord symbol from 4 choices, so `RevealInsight`'s `correctSymbol`/`givenSymbol` contrast line applies directly (identical shape to Drills' chord-identification branch). Mode A grades a played note set, which has no "given symbol" to contrast — it keeps the merged feedback keyboard instead, exactly mirroring Drills' construction branch, which also never shows `RevealInsight`.

## Mode Surfaces

Every mode surface below replaces or extends the `{#if currentFact.factKind === ...}` /  mode-dispatch block inside RecallSession's existing `reviewing` state. The "N LEFT TODAY" register at the top of the card is unchanged. Immediately below it (new, all modes) sits the mode-signal chip:

```html
<p class="text-label mt-2 font-mono uppercase" data-testid="recall-mode-chip">
  {MODE_LABELS[currentItem.mode]}
</p>
```

```
MODE_LABELS = {
  formula:        'SYMBOL → FORMULA',
  'formula-build': 'FORMULA → BUILD',
  'see-play':      'SYMBOL → PLAY',
  'hear-name':     'SOUND → NAME'
}
```

### Mode A — `see-play` (see symbol, play notes)

**Scope:** chord-formula facts only (Scope Decision 2).

**Prompt state (unanswered):**
- `ChordGlyph` for the fact's chord (`root`, `quality` — same derivation RecallSession already uses for the `formula` mode's prompt: `spellChord(currentFact.symbol)`).
- Body line: "Play it on the keyboard."
- `PianoKeyboard` in `interactive` mode: `notes={[]}` (no highlight — nothing is revealed yet), `selected`, `onToggle`, `onPress` wired exactly like Drills' chord-construction branch (self-measuring width, no forced `octaves`, key-touch sound via `pressKey`-equivalent calling `ensureAudioReady()` + `playNote()`).
- Below the keyboard, a two-button row: "Check" (primary, `flex: 3`, `disabled={selected.size === 0}`) and "Clear" (ghost, `flex: 1`) — same 3:1 ratio Drills' `.drill-controls` uses, reused as a local style in RecallSession, not a shared class.

**On Check tap:**
1. Compute `matchChord(selectedChroma, target)`.
2. Write the FSRS grade immediately: `Rating.Good` if `result.correct`, else `Rating.Again` (Scope Decision 4). This write must never block the UI (fire-and-forget with a swallowed catch, mirroring BuildSession's WR-03/RecallSession's existing audio-failure convention).
3. Render feedback:
   - **Correct:** keyboard stays exactly as the user left it (no transform); a confirmation line below picks from `CORRECT_VARIANTS` (no-immediate-repeat picker, reused verbatim).
   - **Wrong:** the SAME keyboard element transforms in place — `notes={target.notes}` (interval-color fill), `wrongLetters={extraLettersPlayed}` (gray fill + ✕), stamp-in reveal animation, exactly Sketch 001 Variant A / PianoKeyboard's existing feedback-mode props. A one-line legend below it: swatch + "The chord", swatch + "Your extra note" (verbatim from `drill-feedback.md`). Headline picks from `WRONG_VARIANTS`.
4. A "Next" button (primary) appears once feedback is shown; tapping it advances the recall queue (same `advanceQueue`/state-reset shape RecallSession's grade buttons already use, just triggered by one button instead of four).

### Mode B — `hear-name` (hear chord, pick name)

**Scope:** chord-formula facts only. Never gates or blocks completion (D-04, locked).

**Prompt state (unanswered):**
- Body line: "Listen. Name the chord."
- Play button (primary): label "Play" on first tap, "Play again" on every subsequent tap while unanswered. Tapping calls `ensureAudioReady()` then `playChord(chord.notes.map(n => n.letter))` (verbatim reuse of the exact call RecallSession's `handleReveal` already makes for the `formula` mode). No auto-play on mount (browser gesture requirement).
- 4-choice grid below the Play button, generated once per card: `shuffle([fact.symbol, ...pickDistractors(fact.symbol, 3)])` (verbatim reuse — `pickDistractors` already guarantees same-root). Rendered as the exact `choice-grid` pattern from Drills (`grid grid-cols-2 gap-2 xl:grid-cols-4`, each choice a ghost `Button` with the symbol in `font-serif text-heading font-bold`, `disabled={answered}`).

**On choice tap (D-05 "tapping IS the answer," reused convention):**
1. `answered = true` immediately; the tapped choice is `given`.
2. Write the FSRS grade immediately: `Rating.Good` if `given === fact.symbol`, else `Rating.Again` (best-effort, swallowed catch — this write NEVER blocks or delays the advance, satisfying "never gates").
3. Confirmation line: `CORRECT_VARIANTS`/`WRONG_VARIANTS` rotation, same as Mode A.
4. On a wrong answer only: render `<RevealInsight correctSymbol={fact.symbol} givenSymbol={given} />` (verbatim reuse — gives the confusion-contrast teaching line, e.g. "Cm7 has E♭, C7 has E.", for free).
5. Auto-advance the recall queue after 650ms (Scope Decision 6) — no manual Next button, no way to linger, matching the "lowest rotation weight, never gates" mandate literally.

### Mode C — `formula-build` (formula → build), embedded

**Scope:** chord-formula and scale-formula facts (Phase 12's existing scope, unchanged).

**Behavior:** mounts BuildSession's `building` state DIRECTLY for the queue's current fact — the picker screen (root/quality/tonic chips) is skipped entirely, since the fact is already chosen. Every visual element of BuildSession's `building` state is reused verbatim: register line ("STEP {n} OF {n}"), step/WHY lines, the count-up hint toggle, the correct/wrong feedback block (including the notable-spelling enharmonic teaching line and the wrong-pitch-class / wrong-octave diagnostic branches), the `PianoKeyboard` `constructable`/`flashWrongKey` wiring at `octaves={2}` inside its horizontal-scroll wrapper, and the running formula strip.

**On full completion** (`construction.done`, matching BuildSession's existing 650ms settle pacing):
1. The FSRS write already fires immediately per BuildSession's existing WR-03 contract (`ratingForWrongTaps`: 0 → Easy, 1-2 → Good, 3+ → Hard, never Again) — unchanged.
2. Completion beat reuses BuildSession's `complete` state markup verbatim: heading ("Voila. You built {symbol}." / "Voila. {tonic} major, built from scratch."), rule statement, formula strip, `PianoKeyboard` (display-only, `octaves={2}`).
3. **Difference from standalone `/build`:** the "SAVED TO RECALL · FORMULA-BUILD MODE" status line is suppressed (Scope Decision 7). The two exit buttons ("Build Another" / "Recall It Now") are replaced by one primary "Next" button that advances the recall queue.

### Mode D — `notes-symbol`

Deferred (Scope Decision 1). No surface built this phase. `deck.ts`'s `Mode` union does not include `'notes-symbol'`. If a future phase builds it: highlight the fact's notes on a display-only keyboard, 4-way same-root multiple choice (reusing `pickDistractors` again), multiple-choice only per D-05 (`Chord.detect` leaks inversions/enharmonics — never free-text grade it).

## Rotation & Mode Signalling (contract, mostly non-visual)

The visual contract is fully covered by the mode-signal chip above (`MODE_LABELS`) plus the per-mode dispatch in Mode Surfaces — RecallSession's render layer only ever needs to know "what mode is `currentItem.mode`," never "is today a teach day or a review day." The teach-vs-review distinction (RECALL-03) is entirely a queue-composition concern upstream of rendering:

- **Teach (new fact, no existing cards):** introduce `formula`, `see-play`, and `formula-build` cards together, all due now, so they queue back-to-back in the same session (D-06's "A→C→D back-to-back... makes multi-modal encoding felt"). Stagger `hear-name`'s introduction to strictly after the other three have graduated past `State.New` for that fact (memorization-engine.md's explicit "FSRS never gets four brand-new cards for one fact at once" rule) — concretely, `hear-name`'s card is not created at all until the fact's other mode-cards are all `State.Review`.
- **Review (existing fact, multiple due mode-cards):** pick 1-2 of the fact's due mode-cards per encounter, preferring the mode with the lowest `stability` (D-07 "weakest-path targeting"); `hear-name` is always the lowest-priority pick and never the sole gate on session completion.
- This selection lives in a new pure module (Component Reuse Inventory), unit-testable exactly like `session.ts` already is. It changes what `introduceNewCards`/`getDueCards`-equivalent hands to `buildQueue`, not `buildQueue` itself.

No additional chrome is needed to visually distinguish a "teach" queue item from a "review" queue item — the mode chip is the only signal a user needs, and it is present in both cases.

## Recall Map Extension

`MODE_COLUMNS` grows from 1 entry to 4:

```
MODE_COLUMNS = [
  { mode: 'formula',       label: 'Formula' },   // unchanged
  { mode: 'formula-build', label: 'Build' },      // new
  { mode: 'see-play',      label: 'Play' },        // new
  { mode: 'hear-name',     label: 'Name' }         // new
]
```

Column order follows the fading-scaffold progression the app already teaches in: recall the formula → build it → play it → name it by ear (most-scaffolded to least).

**Applicability map (new — governs which cells render a real state vs "not applicable"):**

| Column (mode) | chord-formula rows | interval-size rows | scale-degree rows |
|---|---|---|---|
| Formula | real cell (unchanged) | real cell (unchanged) | real cell (unchanged) |
| Build | real cell | **n/a** | **n/a** |
| Play | real cell | **n/a** | **n/a** |
| Name | real cell | **n/a** | **n/a** |

Justification: `formula-build` only ever gets a card for chord-formula facts today (scale-formula facts use a separate factId not in `allFacts()`, an accepted Phase 12 scope gap this phase does not fix); `see-play`/`hear-name` are chord-only per Scope Decision 2.

**"Not applicable" cell (new, additive to `RecallMap.svelte`'s existing 4-state `deriveCellState` vocabulary — this is a UI-only concept, NOT a 5th `CellState` in `deck.ts`):** computed before calling `deriveCellState`, by checking `fact.factKind` against the applicability map above.

- Texture: flat `--color-paper` fill, no border (deliberately quieter/more recessive than "not-yet-seen," which has a visible `--color-faint` border — the two must read as visually distinct: "not-yet-seen" implies "will happen later," "n/a" implies "will never happen for this fact").
- Glyph: a single "·" (middle dot — reuses the app's existing separator-glyph convention, e.g. BuildSession's "SAVED TO RECALL · FORMULA-BUILD MODE," Drills' score register), `color: var(--color-faint)`, `aria-hidden="true"`.
- `aria-label`: `${factLabel(fact)}, ${column.label}: Not applicable` (same format as every other cell's label, swapping in "Not applicable").
- No entry needed in the legend row — the legend documents the 4 real `CellState`s only; "n/a" is self-evident from its quiet, borderless rendering and its `aria-label`.

```css
.recall-map__cell--not-applicable {
  background-color: var(--color-paper);
}
```

Responsive note: 4 mode columns + the label column on a ~375px phone viewport is tight but workable (`minmax(140px, auto) repeat(4, 1fr)` — same grid-template-columns formula already used for N=1, just re-evaluated at N=4). No horizontal scroll wrapper is introduced; column labels stay single words ("Build"/"Play"/"Name") specifically so they never wrap inside a narrow `1fr` cell on phone width.
