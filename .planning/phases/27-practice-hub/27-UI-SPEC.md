# Phase 27 — UI Design Contract

> Visual and interaction contract for the Practice Hub (`/practice`). Generated by gsd-ui-researcher, verified by gsd-ui-checker.

**Scope discipline:** This is a UI restructure that reuses existing drill screens verbatim. Nearly everything below is "reuse existing contract, no net-new" — pointing at the exact component/token/copy already shipped. Only three things are genuinely new and get prescriptive detail: (1) the `/practice` pre-start landing + its empty state, (2) the per-question family cue for the interleaved queue, (3) the merged session's end-card. Do NOT redesign PianoKeyboard, HintLadder, IntervalScaffold, RevealInsight, ChordGlyph, IntervalChip, BuildSession, ShellVoicingDrill, or ProgressionDrill — the merged session renders the SAME per-family screens the executor already has.

### Empty states (three-tier, modeled on `recall.empty.*` verbatim pattern — same tiers, adapted copy since the song-filter toggle no longer lives on this page)

| Element | Copy |
|---------|------|
| Empty: no deck yet (heading) | "Nothing to practice yet." |

## New-for-this-phase: Screen/State Inventory

`/practice` has exactly these states (mirrors `/recall`'s `pageState` machine shape, adapted):

1. **Loading** — reuse `recall.state.loading` mono line pattern ("COUNTING TODAY'S CARDS...") while the hybrid queue composes (FSRS due-cards fetch + synthetic-item availability check).
2. **Empty — no deck yet** (see Copywriting Contract).
3. **Empty — nothing due** (see Copywriting Contract).
4. **Empty — song-filter hides all due** (see Copywriting Contract).
5. **Pre-start** (populated) — the due-summary register + `Start practice` primary Button, in a `border-ink bg-paper-bright border-2 p-6` card, same chrome as `streak-hero`/`session-end-card`. No mode-picker grid (PRAC-01 — hard constraint, checker must fail any grid of per-family buttons here).
6. **In-session** — renders whichever per-family screen the current queue item belongs to (drills' construction/identification branches, BuildSession embed, ShellVoicingDrill, ProgressionDrill, interval construction/identification) completely unchanged, PLUS the new family-cue chip (below).
7. **Session end** — reuse `session-end-card` verbatim (see Copywriting Contract).
8. **Error** (see Copywriting Contract).

## New-for-this-phase: Family Cue Between Questions

**Decision: extend the existing `question-source-tag` slot; do not add a new component, transition screen, or animation.**

`/drills` already renders a small mono-uppercase tag directly above each question's prompt (`text-label text-muted mb-2 font-mono uppercase`, `data-testid="question-source-tag"`), currently populated conditionally from `SOURCE_TAGS[questionSource]` (song-provenance / weak-list origin tags). For the merged Practice queue:

- Reuse this exact slot, position, and text style.
- Make it **always populated** in the merged session (today it's conditional/blank for many question kinds) with the current queue item's **family** name, mono-uppercase, no icon, no color:
  - `NAME IT`
  - `BUILD IT`
  - `VOICING`
  - `INTERVAL`
  - `PROGRESSION`
- If a source tag (song/weak-list origin) also applies to that item, stack it as a second line directly below in the same style — do not replace one with the other; both are informational mono tags in the same visual register.
- **No transition affordance between questions** — no toast, no slide, no modal, no "next up: X" preview. The session flows question-to-question exactly as `/drills` does today; the tag simply reads differently because the underlying item's family changed. This directly satisfies the roadmap's phone-first, glanceable-layout precedent (Phase 23) and avoids inventing new motion for a single-user app.
- The family-cue color is never accent (vermilion) — it uses `--color-muted`/`--color-ink` exactly like `question-source-tag` today. Accent stays reserved for the `Start practice` CTA only.

## New-for-this-phase: Session Length & Register

**Recommendation (per CONTEXT.md's discretion note): follow drills' bounded-round model, not recall's open-ended queue-drain model** — the roadmap's own phrasing ("round-complete") and the existing `session-end-card` both assume a bounded round with a final tally, which is the cleaner, more glanceable fit for a phone-first single "Start practice" entry point.

- In-session score register: reuse the exact drills format verbatim — desktop: `{asked}/{length} · {correct} ✓ · {streak} streak`; phone (drill-strip, ≤639px): `{asked}/{length} · {correct} ✓`.
- No new register component; the merged host's session-glue state (current item index, correct count, streak) feeds the same markup drills already renders.
