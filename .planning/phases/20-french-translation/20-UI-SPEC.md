## I18N-01: The EN|FR Toggle Component

### What it is

A two-segment button group, visually and structurally identical to the app's existing segmented-toggle pattern (`BuildSession.svelte`'s Chords/Scales `kind-toggle`: `role="group"` wrapping two `Button` instances, `aria-pressed` on each, `variant="primary"` on the active segment / `variant="ghost"` on the inactive one). Do not invent a new toggle visual language — reuse this one verbatim so French/English switching looks like every other binary choice in the app.

```
role="group" aria-label="Language"
  [ EN ]  [ FR ]
```

- Active segment: `variant="primary"` (vermilion fill... NO — see Color section above: this control must NOT take vermilion. Override: active segment uses the same ink-fill pressed state as `SongFilterToggle`'s `[aria-pressed='true']` rule (`background: var(--color-ink); color: var(--color-paper)`), not `Button`'s default primary vermilion. This keeps the toggle in the neutral-chrome register, distinct from vermilion CTAs and drill-feedback accents.
- Inactive segment: ghost — `background: var(--color-paper-bright)`, `color: var(--color-ink)`, 2px ink border (matches `.seg button` in the sketch and `SongFilterToggle`'s unpressed state).
- Minimum touch target: 44px height (Print Shop / mobile-ergonomics rule, already enforced on every button/link in the app). Each segment: `min-width: 44px`, `min-height: 44px`.
- Font: `--font-mono`, `--text-label` (12px/700), `text-transform: uppercase`, `letter-spacing: 0.08em` (matches masthead nav links' own letter-spacing so the toggle reads as one family with the nav, not a foreign import).

### Placement

Sketch 013 winner A: top-right of the app-bar masthead on every page, always visible (rejects Variant B's settings-only placement).

**Real masthead is tighter than the sketch assumed.** The sketch mocked a 6-item nav; the actual `+layout.svelte` masthead carries: brand (`MUSIC LEARN`), a `StreakBadge` compact chip, AND 8 nav links (Lookup, Drills, Build, Recall, Scales, Songs, Theory, Progress) — already wrapping onto a second line via `flex flex-wrap` at narrow widths. Adding a 3rd chrome element (the toggle) makes the top identity row busier, not the nav row. Layout fix, in order of preference:

1. **Split the masthead into two visual clusters within the existing single `<nav>` flex-wrap container** (no new DOM level required, just reordering + a wrapping seam):
   - **Identity row** (always together, first in DOM, right-aligned as a sub-group): `MUSIC LEARN` brand -- `StreakBadge` -- `EN|FR toggle`. This is the cluster the toggle joins, per the sketch's winner (top-right, beside brand-level chrome, not mixed into the nav-links row).
   - **Nav row**: the 8 nav links, in their own wrapping flex div (already how `navLinks` renders today) — unaffected by the toggle.
2. On narrow phone widths this means: line 1 = brand + streak chip + toggle (three small chrome items, all `text-label`-sized, all `min-height: 44px` — this row may itself wrap the toggle to a second sub-line if the phone is under ~360px; that is acceptable, matching the nav's own existing wrap behavior, and is preferable to shrinking the toggle below the 44px touch target).
3. Do NOT shrink the toggle below 44×44 to "make it fit" — per Print Shop's mobile ergonomics rule (established Phase 9), touch targets are non-negotiable; let the row wrap instead.

### States

| State | Visual |
|-------|--------|
| EN active | EN segment ink-filled (`--color-ink` bg, `--color-paper` text); FR segment ghost |
| FR active | FR segment ink-filled; EN segment ghost |
| Hover/focus (either segment) | Existing `Button` ghost hover treatment: no new hover style needed, reuse `.masthead__link:hover` underline-on-focus convention is NOT applicable here (this is a filled/ghost segment, not an underlined nav link) — use the standard button focus ring (already global) |
| Press | `translate(1px, 1px)` press-in, matching `SongFilterToggle`'s `:active` rule and every other Print Shop button |

### Persistence & default

- Store choice under a new localStorage key following the project's `music-learn:*` convention: `music-learn:locale`, value `'en' | 'fr'`.
- Default: `'en'` when the key is absent (first visit, or private/incognito browsing).
- Applies immediately on click (no reload, no confirmation) and survives reload/revisit (read on module init, same pattern as `music-learn:docked-keyboard-collapsed` used before its removal, or the existing `soundEnabled`/`studyMode` persistence pattern in `audio.ts`).
- This toggle is chrome, not a drill/recall input — it must never interfere with `KBD-03`'s exploration-vs-answering distinction; switching language mid-drill does not reset or corrupt in-progress drill/recall state (question/target/session state is untouched; only rendered copy re-derives from the new locale).

## I18N-01/03: Chord Glyph & Symbol Immunity (confirmed, locked)

Chord symbols (`Cm7`, `F♯ø7`) and the serif `ChordGlyph` display NEVER translate, in either language. This is confirmed correct by the current codebase and must stay true after this phase:

- `ChordGlyph.svelte` renders `root` + `quality` verbatim from the theory engine's own spelling (tonal-derived), with zero copy-layer involvement. No i18n key wraps a chord symbol.
- Interval shorthand labels used app-wide (`R`, `m3`, `P5`, `A4`, `m7`, etc. — `IntervalInfo.short`, rendered by `IntervalChip`, `InspectRegister`, `BuildSession`'s formula strip, `RecallSession`'s reveal chips) are quality-first interval notation, not English words — they ALSO stay identical in both languages. Only the human-language long-form companion (`IntervalInfo.long` / `.longFr`, e.g. "minor 3rd" / "tierce mineure") switches with locale; the `longFr` field already exists for exactly this and is the seed the i18n layer should read from rather than re-deriving.
- Solfège syllables (Do, Ré, Mi...) are already language-neutral (used identically today for both letter-primary English UI and the eventual French UI) — no change needed.
- Any planner/executor task that touches `ChordGlyph`, `chordPresentation.ts`'s `symbol`/`root` fields, or `IntervalInfo.short`/`.tonalName` must NOT route them through `t()` or any locale-keyed lookup. This is a hard boundary, not a style preference — verify with a grep-based check in the executor's own tests (e.g., assert `Cm7`/`F♯ø7` render identically with `locale` set to `'fr'` and `'en'`).

## I18N-03: Fixed-Slot Fit Rules Per Surface

General principle from sketch 013's audit: French runs ~15-25% longer than English. The danger is fixed-width uppercase mono slots, not prose (sentences wrap fine and need no fix). Below is the surface-by-surface fit rule, grounded in the ACTUAL current markup (not the sketch's illustrative mock, which used hypothetical widths).

### 1. Register / interval-role labels — LOW RISK, corrected finding

The sketch's stress panel imagined a 92px fixed-width grid of full English words (`ROOT`/`THIRD`/`FIFTH`/`SEVENTH`) that FR (`FONDAMENTALE`/`TIERCE`/`QUINTE`/`SEPTIÈME`) would blow out. **The real app does not have this surface.** Every place the app actually shows an interval role, it uses one of two safe forms:

- **Quality-first shorthand** (`R`, `m3`, `P5`, `m7`) — language-neutral, already used everywhere (`IntervalChip`, keyboard corner badges, formula strips). No translation, no overflow risk, ever.
- **Full-word captions above flex-wrapped rows** (`BuildSession`'s "Root" / "Quality" / "Tonic" picker captions) — these are block-level `<p>` elements above a `flex flex-wrap` chip row, NOT a fixed-width grid cell. French forms (`Fondamentale`, `Qualité`, `Tonique`) fit here with zero layout risk; translate them as full words, no abbreviation needed.

**Fit rule (forward-looking safety net):** if any FUTURE component introduces a genuinely fixed-width (non-wrapping) uppercase-mono badge under ~110px that must hold a full register word, use these short FR forms instead of the long noun, per the sketch-013 audit:

| Role | EN | FR (full, safe in flex-wrap captions) | FR short form (fixed-width fallback, use only if the slot is genuinely fixed-width and < 110px) |
|------|----|----|----|
| Root | Root | Fondamentale | FOND. |
| Second | Second | Seconde | SEC. |
| Third | Third | Tierce | TIERCE (already short, no abbreviation needed) |
| Fourth | Fourth | Quarte | QUARTE (already short) |
| Fifth | Fifth | Quinte | QUINTE (already short) |
| Sixth | Sixth | Sixte | SIXTE (already short) |
| Seventh | Seventh | Septième | SEPT. |

Only Root and Seventh need the abbreviated fallback; the others are already interval-notation-short in French. Prefer the flex-wrap-caption pattern (full word, no abbreviation) over introducing a new fixed-width slot in the first place.

### 2. Grading buttons (Again/Hard/Good/Easy) — LOW RISK, already responsive

`RecallSession.svelte`'s grade row is `class="mt-4 grid grid-cols-2 gap-2 sm:grid-cols-4"` — it is ALREADY a responsive 2×2-below/4-across-at-sm-and-up grid, not a fixed 4-across-always layout as the sketch assumed. This means:

- On narrow phones (below the `sm` breakpoint), the grid is already 2×2 — French's longer labels (`Difficile`, `À revoir`) have a full half-row width each, no fix needed.
- At `sm` and wider (≥640px), 4-across has ample width for these FR labels (longest is `Difficile`, 9 chars, `Correct`/`Facile` are equal-or-shorter than EN) — no overflow at any realistic viewport ≥640px with 12-16px mono type.

**Fit rule:** keep the existing `grid-cols-2 sm:grid-cols-4` breakpoint unchanged for both languages — it already solves the sketch's concern. No 2×2-in-FR-only override is needed; the breakpoint is width-driven, not language-driven, which is simpler and correct. Use these exact FR grade labels (Print Shop voice, no em dashes):

| EN | FR |
|----|----|
| Again | À revoir |
| Hard | Difficile |
| Good | Correct |
| Easy | Facile |

The day-interval sub-label under each grade button (`intervalTag(grade.rating)`, e.g. "1d") stays numeric/language-neutral — no translation needed there.

### 3. Nav (masthead links) — LOW RISK, already wraps

The masthead's nav-links container is `flex flex-wrap gap-x-2 gap-y-1 md:gap-4` — links already wrap to additional lines on narrow viewports; this is NOT the sketch's `overflow-x: auto` single-row-scroll pattern. Longer French labels (`Exercices`, `Théorie`) simply cause more/earlier wrapping, never clipping or a forced horizontal scrollbar.

**Fit rule:** do not abbreviate nav labels — full French words render correctly today's flex-wrap layout handles the extra width by wrapping. Use these exact nav labels:

| Route | EN | FR |
|-------|----|----|
| `/` | Lookup | Rechercher |
| `/drills` | Drills | Exercices |
| `/build` | Build | Construire |
| `/recall` | Recall | Révision |
| `/scales` | Scales | Gammes |
| `/songs` | Songs | Morceaux |
| `/theory` | Theory | Théorie |
| `/progress` | Progress | Progrès |

(These differ from sketch 013's own example set, which mocked a 6-item nav guessing at "Revision"/"Progres" without accents — the app's real nav has 8 items; use correct French orthography with accents, e.g. `Révision`/`Progrès`/`Théorie`, since the mono font stack (`Courier New`) and sans stack both render Latin-1 accented characters natively — no transliteration needed.)

### 4. Recall Map mode-column headers — LOW RISK

`RecallMap.svelte`'s `MODE_COLUMNS` labels (`Formula`, `Build`, `Play`, `Name`) sit in a CSS grid with `minmax(140px, auto) repeat(4, 1fr)` — flexible `1fr` columns, not a fixed narrow width. French equivalents are comparable length or shorter:

| EN | FR |
|----|----|
| Formula | Formule |
| Build | Construire |
| Play | Jouer |
| Name | Nommer |

No layout change needed; "Construire" (10 chars) is the longest and still fits an `1fr` column comfortably at the map's minimum viewport width.

### 5. Mode-signal chip (`MODE_LABELS` in RecallSession, e.g. "SYMBOL → FORMULA")

These render as a standalone `<p class="text-label ... uppercase">` line, not a fixed-width badge — full-sentence-width, wraps if needed. Translate as full phrases; no fixed-slot risk. FR forms:

| EN | FR |
|----|----|
| SYMBOL → FORMULA | SYMBOLE → FORMULE |
| FORMULA → BUILD | FORMULE → CONSTRUIRE |
| SYMBOL → PLAY | SYMBOLE → JOUER |
| SOUND → NAME | SON → NOMMER |

### 6. SongMark / SongFilterToggle (Phase 18 new copy, MUST cover per CONTEXT.md)

- `SongMark.svelte`'s multi-song tag (`"{N} SONGS"`, uppercase mono, `white-space: nowrap`, inline `<span>` with 2px border, no fixed max-width — it grows with content) → FR: `"{N} MORCEAUX"`. No overflow risk (nowrap span sizes to content, not a fixed box); single-song form `"♪ {songName}"` is unaffected (song name is user data, not translated).
- `SongFilterToggle.svelte`'s `poolLabel` prop (caller-supplied, e.g. "PRACTICE POOL") and the fixed button copy `"From my songs"` → FR button label: `"Depuis mes morceaux"` (20 chars vs EN's 14 — the button is `display: inline-flex` with `white-space` not set to nowrap on the button itself, only on the badge before it; wraps safely inside its flex row, `min-height: 44px` unaffected). `noteOn`/`noteOff` explanatory sentences are prose — translate in full, no fit risk.

### 7. Interactive Lesson (Phase 19 new copy, MUST cover per CONTEXT.md)

`InteractiveLesson.svelte`'s controls (`"Hear it"` ghost button, `"Continue"` primary button, `"Try this in a drill →"` handoff CTA) are all `Button` components sized to their own content (`padding` + `min-height: 44px`, no fixed width) — French forms fit with zero risk:

| EN | FR |
|----|----|
| Hear it | Écouter |
| Continue | Continuer |
| Try this in a drill → | Essayer dans un exercice → |

The `"FROM YOUR LESSON"` drills-source tag (mirrors `SongMark`'s nowrap-span pattern, same no-fixed-width safety) → FR: `"DE TA LEÇON"`. The four thirds-lesson step titles/bodies in `src/lib/lessons/thirdsLesson.ts` are prose sentences (do-then-check instructions) — translate in full; they already wrap in their step card, no fixed slot.

### Sentences (drill prompts, hints, mnemonics) — confirmed no fix needed

Per sketch 013's own audit and confirmed against the real `text-body`/`text-heading` prompt elements (e.g. RecallSession's `"What's the formula?"`, `"C to {targetLetter}"`): these are unconstrained block text, wrap normally. Translate `src/lib/copy/hints.ts`, `mnemonics.ts`, `streak.ts` in full prose; no abbreviation, no layout change.
