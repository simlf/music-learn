## Typography

Existing 4-size/2-weight contract (unchanged — this phase reuses it exactly, no new sizes):

| Role | Size | Weight | Line Height |
|------|------|--------|-------------|
| Body | 16px | 400 | 1.5 |
| Label | 12px | 700 | 1.4 |
| Heading | 20px | 700 | 1.2 |
| Display | 56px | 700 | 1.05 |

**Phase 19 usage:**
- Step title ("The bottom note", "A major third is 4 keys up", ...) uses **Body** role at weight 700 in `font-serif` (matches the existing `.step-title` shape from sketch 012, sized down from Heading since it sits inside a compact step card, not a page header).
- Step-number badge (`1`, `2`, `3`, `4`) uses **Label** role, `font-mono`, inside a 2px ink border box — identical treatment to the app's other mono metadata badges (tier chips, `SOURCE_TAGS` labels on `/drills`).
- Step body sentence uses **Body** role, `font-sans`, 1.5 line-height — plain reading copy, no serif (serif is reserved for the title and for chord/interval names elsewhere in the app).
- Inline emphasis inside step body (the specific interval word, e.g. "**major third**") is **Body** weight 700, colored `var(--color-third)` (verdigris) — reuses the existing inline-emphasis pattern already used for `.hl` spans in the sketch and for interval-colored text elsewhere (e.g. `IntervalChip`). Never introduce a third inline color for this; the lesson is entirely about the 3rd role, so verdigris is the only inline accent needed.
- Check-line (correct/retry feedback under the keyboard) uses **Label** role, `font-mono`, matching the app's existing register-line typography (`check-line`/`score-register` precedent).
- Handoff card heading ("Now make it stick") uses **Heading** role, `font-serif`, matching every other card heading in the app (Progress streak hero, Drills end card).

## Color

Existing 60/30/10 Print Shop split (unchanged):

| Role | Value | Usage |
|------|-------|-------|
| Dominant (60%) | `--color-paper` `#f2ecdd` | Page background |
| Secondary (30%) | `--color-paper-bright` `#faf6ea` | Step cards, the mini keyboard's white keys, the handoff card's inner chip background |
| Accent (10%) | `--color-vermilion` `#c8502e` | Reserved for: (1) the primary "Try this in a drill →" CTA button, (2) the active step's left-border indicator (`border-left: 8px solid vermilion`), (3) the anchor/root note's key fill on the mini keyboard (locked override — see below), (4) the wrong-tap retry check-line's text and icon |
| Destructive | not applicable this phase | No destructive action exists in a lesson (no delete/reset-progress control this phase — lesson state is in-memory only, per the deferred cross-session persistence) |

**Accent reserved for (explicit, phase-scoped list — never any other element):** the four uses above. Do NOT use vermilion for the "done" step's left border (that's verdigris, matching interval-color semantics — see below) or for any other chrome.

**Locked override from sketch 012:** the sketch renders the anchor/bottom note (C) with a flat ink fill (`.lit-anchor { background: var(--color-ink) }`), distinct from the interval-color language. This phase overrides that: DESIGN-02 requires the fixed interval-color language apply consistently "across drills, lookup, and lessons," and the anchor note in a major/minor-third lesson **is** the interval's root. It must render with `--color-root` (`#c8502e`, same value as vermilion) exactly like every root note elsewhere in the app — a plain ink fill would be a second, lesson-only visual language for the same semantic role. Both the tapped major-third and minor-third notes use `--color-third` (`#3e7d6b`, verdigris) — the SAME color for both, since the app's interval-color language colors by **scale-degree role** (3rd), not by quality (major vs minor); the quality distinction is carried by pitch, sound, and copy, never by a second accent color.

- "Done" step's left-border accent: `--color-verdigris` (`#3e7d6b`), matching CONTEXT's "correct tap: verdigris light" instruction and the third-role color already in use for the tapped note — no separate token needed, they are the same variable.
- Wrong-tap flash on the keyboard: reuses the EXISTING `--color-wrong` / `--color-wrong-deep` grays via `PianoKeyboard`'s `flashWrongKey` prop (Phase 12's construct-mode wrong-tap indicator) — never vermilion, never a new gray.
- Locked step's step-num badge: `background: var(--color-verdigris); color: #fff` (mirrors sketch's `.step[data-state="done"] .step-num`), consistent with the on-fill white-text rule already declared for verdigris in `app.css` (`--color-on-third: #ffffff`).

## Phase-Specific Contract

### Component Inventory

**1. `InteractiveLesson.svelte` (new)**

New component, single instance this phase (the major/minor-third lesson), imported into `src/routes/theory/+page.svelte`. Built extensible for future lessons (per CONTEXT's "format must be extensible"), but only this one lesson's content ships — no lesson-picker/registry needed yet.

Step data shape (discretion-resolved, mirrors the sketch's `A_STEPS` array almost verbatim):

```ts
interface LessonStep {
  title: string;
  body: string; // may contain one inline-emphasized interval phrase
  /** Target chroma (0-11) relative to C=0. null = a pure "hear it, then continue" step with no tap to grade. */
  targetChroma: number | null;
  /** Interval role this tap earns, for the notes[] fill once correct. */
  role: 'root' | 'third' | null;
  /** Whether a Hear/Hear again control appears once this step is active or done. */
  hearable: boolean;
}
```

Four steps ship, in this exact order (content locked above): anchor (root, chroma 0) → major third (third, chroma 4) → hear it (no tap, `targetChroma: null`) → minor third (third, chroma 3).

**2. Keyboard wiring (reuse `PianoKeyboard.svelte` verbatim, `constructable` mode)**

Locked pattern: reuse Phase 12's `constructable`/`onConstructTap`/`flashWrongKey` contract exactly as `BuildSession` already uses it — do NOT build new tap-handling logic, and do NOT reuse the Drills page's `interactive`/`selected`/`wrongLetters` (permanent-reveal) pattern, which is shaped for multi-note chord assembly, not this lesson's single-tap-per-step grading.

```svelte
<PianoKeyboard
  octaves={1}
  notes={earnedNotes}
  constructable={!stepDone && step.targetChroma !== null}
  onConstructTap={handleTap}
  flashWrongKey={wrongFlash}
  pulseToken={hearPulseToken}
/>
```

- `earnedNotes`: a `SpelledNote[]` accumulating one entry per completed step (`{ letter: 'C', solfege: 'Do', role: 'root' }`, then `{ letter: 'E', solfege: 'Mi', role: 'third' }`, then after step 4 that entry is REPLACED — not appended — by `{ letter: 'E♭', solfege: 'Mi', role: 'third' }`, since only one third is "currently held" at a time: the lesson is a contrast, not a four-note chord). This keeps the interval-color language legible (never two different notes both claiming the "third" role simultaneously on the same keyboard).
- Grading (`handleTap`): compare `Note.chroma(toAsciiAccidentals(letter))` against `step.targetChroma` (locked v2 constraint: chroma/MIDI only, never letter-string comparison) — mirrors `gradeIntervalTap`'s existing pattern in `$lib/drills/generateIntervalQuestion.ts` almost exactly; consider calling it directly rather than reimplementing.
- Correct tap: set `earnedNotes` to include the new role-colored note, fire `pressKey`-equivalent audio (`playNote` for the tapped pitch, existing `ensureAudioReady()` gate), bump `stepDone`, reveal the check-line + Hear/Continue controls.
- Wrong tap: set `flashWrongKey = { letter, octave: 4 }` for ~450ms (mirrors the sketch's exact timing and `BuildSession`'s existing flash duration), render the retry check-line with the semitone-distance hint, do NOT advance, do NOT fire audio for the wrong note (per BuildSession's existing "wrong taps never call playNote — caller owns feedback" contract; this lesson's caller intentionally plays nothing on a miss, keeping the only sounds heard the correct target notes).
- "Hear it"/"Hear again" control: calls `playChord(['C', <third letter>])` (or `playNote('C')` alone for step 1) via the existing `playChord`/`playNote` audio contract, respecting `soundEnabled()` automatically (no manual gating needed, matches every other call site), and bumps `pulseToken` so the already-lit key(s) pulse in sync (Phase 16's established `pulse-once` pattern) — this is the audible LEARN-02 requirement.
- With sound disabled: `playChord`/`playNote` no-op internally (existing `soundEnabled()` guard); the tap/step-advance/pulse logic must NOT be gated on sound state — steps still lock and advance purely visually, per LEARN-02's explicit "sound-off still advances" clause.

**3. Step card visual states**

Locked structure (mirrors sketch 012-A's `.step`/`.step-num`/`.step-body` almost verbatim, ported to Tailwind + the app's existing utility conventions rather than raw CSS):

| State | Left border | Opacity | Step-num badge | Content shown |
|-------|-------------|---------|-----------------|----------------|
| locked | none (plain 2px ink border all around, matching every other Print Shop card) | 0.4 | plain ink border, ink text | title + body only, no keyboard, no controls |
| active | `border-left: 8px solid var(--color-vermilion)` | 1.0 | plain ink border, ink text | title + body + keyboard + check-line (once a tap occurs) |
| done | `border-left: 8px solid var(--color-verdigris)` | 1.0 | `background: var(--color-verdigris); color: #fff` | title + body + a collapsed one-line recap (no live keyboard re-render needed once locked, reduces DOM churn) + a small "done" chip (Label role, verdigris text, uppercase, matches sketch's `.done-chip`) |

Card container: `border-2 border-ink bg-paper-bright px-4 py-6` — identical to every existing `/theory` section wrapper (`section-symbol`, `section-sevenths`, etc.) and every Drills card, for visual consistency with the rest of the app. Steps stack with `gap: var(--spacing-lg)` (24px) between them (matches `.steps` in the sketch).

**4. Handoff card**

Structure locked (mirrors sketch's `.handoff` almost verbatim): `bg-ink text-paper-bright` inverted card (identical color-inversion pattern to the Drills wrong-answer feedback headline block, `bg-ink p-4`, and to `RecallSession`'s completion cards) — this is the ONE place in this phase that inverts the palette, reserved for the "lesson complete, moving on" moment, matching the app's existing use of ink-inversion exclusively for milestone/transition moments (never for routine content).

- Eyebrow: Label role, `color: var(--color-mustard)` (matches sketch's `.handoff .reg`, and matches the app's existing mustard-on-ink eyebrow convention used in Drills' wrong-headline block).
- Heading: Heading role, serif.
- Body: Body role, `color: var(--color-paper)` at reduced opacity (~0.85, matches sketch), for the ink-background legibility already established elsewhere.
- Chip ("C · Cm"): serif, Heading size, no special background (sits directly on the ink card).
- CTA: `Button variant="primary"` but with the handoff's card-specific override — background `var(--color-mustard)`, text `var(--color-ink)` (matches sketch's `.handoff .btn` override exactly, since a vermilion-on-ink button would clash badly with the ink card's own coloring; mustard-on-ink is the established "CTA sitting on an inverted card" treatment already used elsewhere, e.g. Progress's streak hero card buttons).

Only rendered once `stepDone` is true for all four steps (never before — matches the sketch's `.handoff.hidden` gate exactly).

### Drill Handoff Mechanism (LEARN-03)

Locked: reuse the EXISTING one-shot `setDrillSeeds(symbols: string[])` / `consumeDrillSeeds()` plumbing verbatim (`src/lib/practice/drillSeeds.ts`, already used by Progress's "Drill these" button) — do not invent new persistence plumbing for this handoff.

- On CTA tap: call `setDrillSeeds(['C', 'Cm'])`, then navigate to `/drills` (matches `Button href="/drills"` navigation semantics already used elsewhere on `/theory`'s own existing "Take it to the drills" CTA at the page's bottom — this new handoff sits ABOVE the interactive lesson section, this is a second, more specific CTA scoped to the two triads that make the lesson's contrast concrete).
- The two seeded chords are literally "the chords built from" the major and minor third the user just tapped (C major triad's middle note is the major third E; C minor triad's middle note is the minor third E♭) — directly satisfying CONTEXT's "seeded to the lesson's focus" requirement without introducing a new interval-family session-item type.
- Copy requirement: the Drills page's existing `SOURCE_TAGS` map (`{ warmup: ..., retry: ..., seeded: 'FROM YOUR WEAK LIST' }`) must NOT silently relabel this lesson-originated seed with "FROM YOUR WEAK LIST" copy (that string implies a weak-item redrill, which this is not). The rendered label for lesson-originated seeded questions must read **"FROM YOUR LESSON"** instead. Wiring this (a distinct `QuestionSource` variant, or an origin flag threaded through `consumeDrillSeeds`/`createSession`) is left to the planner as an implementation detail; the exact copy is locked here.

### /theory Page Integration

Locked placement: the `InteractiveLesson` section is inserted as the **first** section on `/theory`, above the existing "Reading a chord symbol" (`section-symbol`) section, using the identical section-wrapper shape every other `/theory` section already uses (`border-2 border-ink bg-paper-bright px-4 py-6`, `data-testid="section-interactive-lesson"`). The page's existing header ("Theory" / lead paragraph) and all five existing static lesson sections stay completely unchanged, byte-identical, below it — per CONTEXT's explicit "do not remove existing theory content."

No tab/toggle is introduced to switch between "interactive" and "static" content — the page is simply a top-to-bottom scroll, interactive lesson first (it is the primary surface per CONTEXT), static reference lessons following, matching the single-scroll shape the rest of `/theory` already has.

### Persistence

Locked (per CONTEXT's explicit deferral): step-completion state is `$state` only, scoped to the mounted component's lifetime. A page reload resets the lesson to step 1. No `localStorage` key, no lesson-map, no unlock-gating this phase — this is the deferred "Variant B" concern, out of scope.

### Accessibility

- Step cards: no special ARIA role needed (they are not a wizard/dialog, just a document flow of cards); locked steps' non-interactive keyboard is simply absent from the DOM (no `aria-disabled` gymnastics needed since there's nothing interactive to disable).
- Keyboard taps: `PianoKeyboard`'s existing `constructable` mode already provides correct button semantics (real `<button>` elements, Enter/Space activation) — no new work needed.
- Check-line feedback: rendered as a plain text row (Label role), not `role="alert"` — matches the existing Drills/BuildSession check-line precedent (none of them use `aria-live`), so this phase stays consistent rather than introducing a one-off live-region pattern.
- Color is never the only signal: the done/active/locked step states differ by opacity AND left-border AND badge fill (three simultaneous signals), and major vs minor third differ by copy text and pitch, never by color alone (both are verdigris, per the locked interval-color-language override above).
- Handoff CTA: real `<a href="/drills">` via `Button`'s existing `href` prop, not a JS-only click handler pretending to be a link.
