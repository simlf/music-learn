<objective>
Build the `/recall` Review-mode experience: a new `RecallSession.svelte` component driving the reveal-then-grade session loop (loading a due-today queue, revealing each fact's answer, grading it Again/Hard/Good/Easy with live day-interval-labeled buttons, and completing the session), wired into a new `/recall` route with a masthead nav entry (MEM-01, MEM-02).

Output: RecallSession.svelte + its test, the new /recall page, and the masthead nav link. The Map mode and recall grid (MEM-04) are NOT part of this plan (see 11-06); this plan's page renders Review-mode content only.

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| grade-button tap -> recordGrade | The user's only input on this page is tapping one of four fixed buttons (Again/Hard/Good/Easy) or "Show Answer"/"Practice Now"/"Try Again"; there is no free-text input and no user-supplied identifier reaches deck.ts — every call passes a Rating enum value or a CardRecord already read from the local deck. |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-11-08 | Tampering | grade button click handlers | low | mitigate | Each of the four grade buttons is wired to a hardcoded `Rating` enum value at build time (Again/Hard/Good/Easy); there is no dynamic/user-controlled rating identifier and no way to submit an out-of-range rating. |
| T-11-09 | Denial of Service | async deck calls (introduceNewCards/getDueCards/getAllCards/recordGrade) | low | mitigate | Every awaited call is wrapped in try/catch, surfacing the dedicated `error` page state rather than an uncaught promise rejection; the session queue is always bounded (NEW_CARDS_PER_SESSION cap plus whatever was already due), so there is no unbounded loop. |

No new package installs are introduced by this plan (all dependencies were installed in 11-01/11-03). T-11-SC is not applicable here.
</threat_model>
