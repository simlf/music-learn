# Phase 8 — UI Design Contract

> Visual and interaction contract for frontend phases. Generated by gsd-ui-researcher, verified by gsd-ui-checker.

**Mode:** Fully autonomous (no CONTEXT.md/RESEARCH.md exist for this phase; Phases 1-3 established the pattern of Claude making sound design calls without stopping to ask). Genuinely ambiguous points are flagged inline as `> OPEN QUESTION` rather than left unanswered.

## Design System

| Property | Value |
|----------|-------|
| Tool | none |
| Preset | not applicable |
| Component library | none (hand-rolled Svelte 5 components) |
| Icon library | none (no icon system anywhere in the app; typography, chord glyphs, and mono status text carry all signaling) |
| Font | System stacks only, no webfonts: `--font-sans` (UI text), `--font-serif` (chord symbols only), `--font-mono` (status/data labels) — carried unchanged from Phase 1 |

No `components.json` exists and none should be introduced. Phases 1-3 built and matured a bespoke "Print Shop" token system (`src/app.css`) and component set; shadcn/shadcn-svelte was never adopted and introducing it three phases in would fragment the design language for no benefit. This phase extends the existing system only.

### New components this phase introduces

| Component | Purpose | Notes |
|-----------|---------|-------|
| `StreakBadge.svelte` | Renders the daily-practice streak count | Two size variants: `compact` (masthead chip) and `hero` (Progress page headline). Same component, different prop, so copy/logic don't fork. |
| `PracticeItemRow.svelte` | One row in "Weakest Spots" and the full stats table | Handles both `kind: 'chord'` and `kind: 'scale'` items; renders a kind tag, symbol/name, attempts, accuracy%, and the "needs practice" accent bar. |
| `AccuracyTable.svelte` (or inline `<table>` composition) | Full per-item stats list, alphabetical or accuracy-sorted | Reuses `PracticeItemRow`. |
| Progress page states | Loading / empty / error / populated | See Copywriting Contract below for exact strings. |

### Reused, unchanged

`Button.svelte`, `IntervalChip.svelte`, `NoteLabel.svelte`, `PianoKeyboard.svelte` (not needed on this page unless a "here's the shape" quick-peek is added later — out of scope for v1 of this phase), `ChordGlyph.svelte` (explicitly NOT reused for list rows — see Typography note below), masthead in `+layout.svelte` (extended, not replaced).

## Spacing Scale

Declared values (must be multiples of 4) — unchanged from Phase 1, reused as-is:

| Token | Value | Usage |
|-------|-------|-------|
| xs | 4px | Icon-free inline gaps (e.g. kind-tag to symbol) |
| sm | 8px | Compact element spacing (row internal gaps) |
| md | 16px | Default element spacing (card internal padding) |
| lg | 24px | Section padding, gap between Progress page sections |
| xl | 32px | Layout gaps |
| 2xl | 48px | Major section breaks (streak hero to Weakest Spots) |
| 3xl | 64px | Page-level spacing |

Exceptions:
- 44px minimum touch target (carried Phase 1/2/3 exception) applies to every tappable `PracticeItemRow` (if wired to a drill deep-link — see Copywriting note) and to the masthead streak chip if it is ever made tappable. Row padding must clear 44px even though single-line text content would naturally be shorter.
- No new exceptions beyond the carried one.

## Typography

Sizes/weights are unchanged from Phase 1 (still exactly 4 sizes, 2 weights: 400, 700) — this phase does NOT add a new size.

| Role | Size | Weight | Line Height |
|------|------|--------|-------------|
| Body | 16px | 400 | 1.5 |
| Label | 12px | 700 | 1.4 (mono, `letter-spacing: 0.14em`, uppercase) |
| Heading | 20px | 700 | 1.2 |
| Display | 56px | 700 | 1.05 |

**New usage rule this phase establishes:** `text-display` was previously reserved for `ChordGlyph` (serif, always a chord symbol). This phase reuses `text-display` for the streak hero numeral, but ONLY in `font-mono`, never `font-serif`. The rule going forward: **Display size + serif = chord glyph. Display size + mono = a big data numeral (streak count).** They must never be confused because the font family always disambiguates.

Practice list rows use `text-heading` (20px, sans, bold) for the chord/scale symbol, NOT the full `ChordGlyph` component — `ChordGlyph` is display-sized (56px) with a misregistered print-shadow, sized for a single hero chord and too heavy to repeat 5-20 times in a list.

## Color

| Role | Value | Usage |
|------|-------|-------|
| Dominant (60%) | `#f2ecdd` (paper) | Page background |
| Secondary (30%) | `#faf6ea` (paper-bright) | Cards: streak hero card, Weakest Spots card, stats table card — all bordered `2px solid var(--color-ink)`, matching the existing `drill-card` pattern from Phase 3 |
| Accent (10%) | `#c8502e` (vermilion) | See reserved list below — do not introduce a new "weak item" color |
| Destructive | not applicable | No destructive actions in this phase (no delete/reset-history feature is in PROG-01/02/03 scope) |

**Accent reserved for** (vermilion, `#c8502e`):
1. Primary CTA buttons on this page: "Practice Now" (populated state) and "Start a Drill" (empty state).
2. The streak hero numeral, but ONLY when the streak is active (count ≥ 1). A zero streak renders the numeral in ink (`#221e17`), never vermilion, so vermilion stays a reward signal, not decoration.
3. The 4px left-edge accent bar on `PracticeItemRow`s that fall below the "needs practice" threshold (see below) — an intentional callback to a red-ink ledger correction mark, thematically consistent with the Print Shop metaphor.
4. Carried, unchanged uses from Phase 1 (chord-glyph print shadow, root interval chip) — not exercised on this page since `ChordGlyph` isn't used in list rows.

**Do not use** `--color-third` / `--color-fifth` / `--color-seventh` (verdigris/tan/mustard) anywhere on the Progress page. Those are reserved exclusively for chord-tone interval roles (DESIGN-02) and this page never displays individual chord tones, only aggregate stats. Introducing them here as "accuracy tier" colors would create a second, conflicting meaning for the interval palette — explicitly avoid this.

**"Needs practice" threshold (Claude's discretion, stated explicitly so planner/executor don't re-derive it):** an item gets the vermilion accent bar and bold accuracy text when `attempts >= 3 AND accuracy < 70%`. Items with fewer than 3 attempts are excluded from "Weakest Spots" entirely (not enough data to be meaningful) but still appear in the full stats table, unflagged.

## Copywriting Contract

No em dashes anywhere in this page's copy (project-wide rule) — periods, colons, commas only.

| Element | Copy |
|---------|------|
| Primary CTA (populated state) | "Practice Now" — links to `/drills` |
| Primary CTA (empty state) | "Start a Drill" — links to `/drills` |
| Empty state heading | "Nothing on the ledger yet." |
| Empty state body | "Play a few drills and your stats start showing up here. Weakest spots first, always." |
| Error state | "Couldn't reach the ledger. The server's not answering right now. Check your connection and try again." + "Try Again" retry button (ghost variant, re-runs the fetch) |
| Destructive confirmation | not applicable (no destructive action this phase) |

### Streak copy (rotation pools, mirroring the established `pickHint`/`pickVariant` anti-repeat pattern from Phases 1-3)

Suggested home: `src/lib/copy/streak.ts`, exporting `pickStreakLine(kind, lastIndex)` alongside the existing `hints.ts` module.

**Streak active, already practiced today** (count ≥ 1):
1. "{N} days running. Bravo."
2. "{N} in a row. Et voilà."
3. "{N} days strong. Keep the presses warm."

**Streak active, not yet practiced today** (gentle nudge, never guilt):
1. "{N} days and counting. Play something today to keep it alive."
2. "{N} in a row so far. A few minutes today keeps it going."
3. "{N} days strong. Don't let today be the gap."

**Streak at zero** (first-ever visit or a lapsed streak — identical copy either way, no "you broke it" framing, per Phase 1 D-02 "never scolding"):
1. "No streak yet. Every run starts with day one."
2. "Fresh page. Play a few chords to start the count."
3. "Day one is free. Go stamp something."

**Masthead streak chip** (compact form, mono uppercase, matches the existing `score-register` styling on `/drills`): `"{N} DAY STREAK"` when N ≥ 1. When N = 0, the chip renders nothing (no "0 DAY STREAK" — an absent chip reads better than a discouraging zero in persistent chrome). While the streak is loading, the chip also renders nothing (no skeleton in the masthead — avoid layout jank in a piece of global chrome that must not flash or shift). If the fetch errors, the masthead chip fails silently (omits itself); the full error explanation lives only on the dedicated Progress page.

## Component & Layout Details

### Masthead (extends `src/routes/+layout.svelte`)

- Add `{ href: '/progress', label: 'Progress' }` to `navLinks`, positioned after Drills and before Showcase (user-facing feature order; Showcase stays last as the permanent dev/test page, per Phase 2's own precedent).
- Add the streak chip (`StreakBadge` `compact` variant) between the app name and the nav links on desktop; on the existing mobile `flex-col` stack it sits on its own line below the app name, above the nav links.
- The chip must not block or delay masthead render: nav links render immediately regardless of streak-fetch state (see copy rules above for its own loading/zero/error behavior).

### Progress page (`src/routes/progress/+page.svelte`)

Top to bottom:
1. `<h1>Progress</h1>` (`text-heading`, bold, `mt-2`, matching Drills' `h1` treatment).
2. Streak hero card (`bg-paper-bright`, `border-ink border-2`, padding `lg`): rotation-line copy above, `StreakBadge` `hero` variant numeral below (display size, mono, vermilion when active / ink when zero), "Practice Now" primary button beneath (populated state only — omit on the very first-ever empty state screen, where "Start a Drill" is the sole CTA, to avoid duplicate CTAs).
3. `2xl` gap.
4. "Weakest Spots" card: heading + subcopy, then up to 5 `PracticeItemRow`s (worst accuracy first), each row min-height 44px.
5. `xl` gap.
6. "All Stats" — full `AccuracyTable` of every practiced item (chords and scales together, sorted alphabetically by symbol/name within kind, or accuracy-ascending — planner's call, either is defensible; alphabetical is slightly easier to scan for "did I ever practice X").

**State handling for the whole page:**
- **Loading** (initial fetch from the Oracle-server backend in flight): static placeholder blocks in `paper-bright` at ~10% opacity ink overlay, no shimmer/pulse animation (keep motion minimal per the ≤300ms tasteful-effects rule — a loading skeleton that runs indefinitely is a different category than the brief settle animations elsewhere, so it stays static). Mono label above the blocks: `"FETCHING THE LEDGER..."`.
- **Empty** (fetch succeeded, zero recorded answers ever — first visit before any drill history exists): replace the streak hero + Weakest Spots + All Stats sections entirely with the single empty-state block (heading, body, "Start a Drill" CTA). Do not show empty "0%" rows or a zero-day streak card alongside it — one clear message, one CTA.
- **Error** (fetch failed — Oracle server unreachable, network down, etc.): replace the page body with the error-state block (message + "Try Again" retry button, ghost variant). This is this phase's first true network round-trip (Phases 1-3 were fully client-local), so this state is not optional polish, it is a required path.
- **Populated**: the full layout described above.

> OPEN QUESTION for planner/executor: whether `PracticeItemRow` deep-links into a scoped `/drills` session focused on that specific chord/scale depends on whether Phase 5's session-scoping (DRILL-04) has landed and what query-param/API shape it exposes by the time Phase 8 is planned (Phase 5 precedes Phase 8 in execution order, so it likely has). If that scoping API exists, wire each row's tap target to it (respect the 44px touch target either way). If not, rows are inert (not tappable) and only the page-level "Practice Now" / "Start a Drill" buttons link to plain `/drills`. This is a wiring decision, not a visual one — the row's visual contract (kind tag, symbol, attempts, accuracy%, accent bar) is identical either way.

> OPEN QUESTION for planner: streak day-boundary uses the browser's local calendar date. Single-user, and the user's stated usage pattern (laptop at the piano, phone elsewhere) is presumed single-timezone, so this is a reasonable v1 simplification rather than a gap — flagging so the backend doesn't over-engineer timezone handling PROG-03 doesn't ask for.
