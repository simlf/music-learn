<objective>
Stand up the project's first backend: a small standalone Node service that accepts a graded drill answer over HTTP and persists it to SQLite. This is the server end of the answer-persistence slice (PROG-01). It is deliberately dependency-injected and integration-tested end to end (HTTP request through to a real SQLite row) so it is a working capability, not a stub. The client wiring, Docker packaging, and end-to-end drill round-trip land in 08-02.

## Phase Goal (slice user story)

**As a** returning pianist practicing drills, **I want to** have each graded answer accepted and stored by a backend service, **so that** my practice history is preserved beyond a single browser session.

Purpose: Establish the raw-event storage substrate (D-02) and the bearer-token trust boundary (D-03) exactly once, correctly, before any client depends on it. Keeps the SvelteKit app static (D-01) and isolates all server code under `server/`.
Output: A tested `server/` service exposing `POST /answers` (auth + validation + insert) and `GET /health`, backed by a SQLite `answers` table.
</objective>
