# Phase 30 — UI Design Contract

> Visual and interaction contract for frontend phases. Generated by gsd-ui-researcher, verified by gsd-ui-checker.

**Scope note:** This phase is nav-restructure + routing only. It reuses the EXISTING masthead and phone bottom-tab-bar chrome verbatim (Print Shop identity, ink-fill/paper-text active state, 56px icon+micro-label tab slots — all LOCKED, do not redesign). The only net-new visual surface is 3 tab icons (`/practice`, `/learn`, `/progress`) and a shorter nav-links list. Redirect shims produce no visual output at all (see Redirect Behavior below). Everything else in this contract is "reuse as-is" — recorded here so the executor has zero ambiguity, not because it changed.

## Nav Contract (what's actually new)

### Desktop masthead
- `navLinks` shrinks from 10 entries to exactly 4, in this order: `/` (nav.lookup), `/practice` (nav.practice), `/learn` (nav.learn), `/progress` (nav.progress).
- Rendering, active-state (`masthead__link--active`, underline treatment), hover/focus styling: byte-identical to today. Do not touch `.masthead__link` CSS.

### Phone bottom tab bar
- `bottomTabHrefs` becomes `['/', '/practice', '/learn', '/progress']` — same 4, same order as the masthead. Still derived via `.filter()` over `navLinks` (never a second literal array — existing convention, keep it).
- The "More" affordance is deleted entirely: remove `MORE_ICON`, `moreHrefs`, `moreLinks`, `moreOpen` state, the `<BottomSheet>` import, its markup block, and the More `<button>` in the tab bar. With exactly 4 hubs the 5th "More" slot has no reason to exist.
- Tab slot markup/CSS (icon + 9px micro-label, 56px height, `min-height: 44px`, ink-fill active state): unchanged. 4 slots instead of 4+1 just means one fewer `<button>` sibling — no CSS changes required since `.bottom-tab-bar__item { flex: 1 }` already redistributes width automatically.

## Redirect Shim Behavior (non-visual)

The 8 redirect shims (`/drills`, `/build`, `/voicings`, `/progressions` → `/practice`; `/scales`, `/theory` → `/learn`; `/recall`, `/songs` → `/progress`) render **no intermediate UI whatsoever**. Each shim is a `+page.ts` `load()` that `throw redirect(308, target)` — this is a server/build-time redirect resolved before any component paints, so there is no flash of a loading spinner, an empty shell, or the old page's markup. The user's address bar updates to the target hub and the hub's normal first-paint (whatever that hub's own UI-SPEC already defines) is what they see — nothing about that first-paint changes because the user arrived via redirect versus direct navigation.

If the "Verify the 308 redirect prerenders cleanly" fallback (CONTEXT.md) is needed — a client-side `goto()` redirect instead of a load-throw — that fallback path DOES risk a brief flash of blank content. If forced to use it: render nothing (no spinner, no shim copy) rather than a placeholder screen; keep the flash window as short as possible by calling `goto` synchronously in `onMount`, not after any async work.

|---------|------|

| `nav.practice` (FR) | Pratiquer |
| `nav.learn` (EN) | Learn |

| Empty state | Not applicable — no new empty state in this phase. |
| Error state | Not applicable — no new error state in this phase. |
| Destructive confirmation | Not applicable — no destructive action in this phase (redirects and route deletion are build-time, not user-facing destructive actions). |

Rationale for `nav.practice`/`nav.learn` FR picks: existing nav FR labels mix verb-form ("Rechercher", "Construire") and noun-form ("Exercices", "Gammes", "Morceaux", "Théorie", "Progrès") — no single strict rule to inherit. "Pratiquer"/"Apprendre" match the verb-form entries and read naturally as single-word tab labels at 9px on phone. No em dashes (project-wide rule) — neither label needs one. If the user prefers noun-form ("Pratique"/"Apprentissage") that is a one-line swap in `chrome.ts`, not a structural change to this contract.
