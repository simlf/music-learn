# Sketch 017: Progression Drill

## Design Question

Backlog I-02 (ranked #1 by both research passes): real sheet music is progressions, not isolated symbols. How does a progression drill surface the key, the roman-numeral function, and the chord-by-chord flow, while reusing the existing drill chrome (docked keyboard, serif glyph, stamp-in reveal, interval colors)?

## How to View

open .planning/sketches/017-progression-drill/index.html

## Variants

- **A: Progression rail** — persistent 3-slot rail (done / current / masked upcoming) above the standard glyph + keyboard drill; functional reveal panel after each check.
- **B: Roman-first** — two-step: derive the symbol from the roman numeral via multiple choice, then play it. Trains numeral-to-symbol mapping explicitly.
- **C: Lead-sheet strip** — the drill is the song: a real lead-sheet measure grid (Autumn Leaves, provenance mark) with a moving bar cursor; play in reading order.
- **Synthesis: C sheet + B derive** — C's lead-sheet grid as container (symbols hidden until earned, numerals visible), each cursor bar runs B's two-step: name from numeral, then play. Sheet fills in as you go.

## What to Look For

- Does the rail (A) give enough "where am I in the progression" context without stealing focus from the current chord?
- Is B's derive-then-play two-step teaching or friction?
- Does C feel like practicing real music, and does the 4-bar grid survive 390px width (B♭maj7, E♭maj7 are the widest symbols)?
- Where should the functional reveal live: below the keyboard (A/C) or as the bridge between steps (B)?
